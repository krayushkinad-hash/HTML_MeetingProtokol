# US-053: Полное удаление протокола с каскадом

| Поле | Значение |
|---|---|
| **ID** | US-053 |
| **Эпик** | EPIC-LIFECYCLE |
| **Приоритет** | Must |
| **Story Points** | 3 |
| **Персона** | P-01 Алексей (Windows) |
| **Форма** | ProtocolCard (context menu) + диалог подтверждения |
| **API** | DELETE /api/v1/hmp/protocols/{id}/permanent |

## User Story
**Как** Алексей (P-01),
**я хочу** полностью удалить протокол вместе со всеми связанными данными (реплики, саммари, скриншоты, файлы),
**чтобы** освободить место на диске и убрать ненужные записи навсегда.

## Контекст
- **Процесс:** Полная очистка данных.
- **Боль персоны:** Накопилось много старых протоколов, занимают место.
- **Связь с Vision:** §7.1 Базовое ядро — «Локальная работа с данными».

## Acceptance Criteria

- **AC-1:** Given я на странице протокола, When я нажимаю «🗑 Удалить» и ввожу «DELETE», Then я вижу второе подтверждение «ТОЧНО удалить ВСЕ данные протокола навсегда? Это нельзя отменить!».

- **AC-2:** Given я подтвердил оба раза, When запрос отправляется, Then удаляются все связанные записи: utterances, speakers, tags, action_items, decisions, summary, transcription_tasks, screenshots (+ файлы), audio_file (+ файл).

- **AC-3:** Given удаление завершено, When я перехожу на главную, Then Toast «Протокол удалён. Удалено записей: N» где N — сумма всех удалённых.

- **AC-4:** Given протокол удалён полностью, When я обращаюсь к `/media/...`, Then файл возвращает 404 (не существует).

- **AC-5:** Given протокол удалён, When я проверяю папку `~/.html_mp/protocols/`, Then папка протокола удалена (если была пустой).

- **AC-6:** Given все удалено, When я перехожу на главную, Then протокол не отображается ни в каких списках.

## Технические заметки
- Каскадное удаление в одной транзакции
- Файлы удаляются с диска **только после** успешного удаления из БД
- Если удаление файла не удалось — логируем warning, но продолжаем
- Каскадное удаление в БД не требует `CASCADE` если удалять через SQL явно
