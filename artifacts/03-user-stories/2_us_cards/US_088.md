# US-088: Редактирование атрибутов протокола

**Приоритет**: P1 (US-001..US-087 уже реализованы)
**Категория**: US (User Story)
**Зависимости**: US-001 (создание протокола), PATCH /protocols/{id}

## Описание

Пользователь может редактировать атрибуты существующего протокола:
- **title** — название протокола
- **chair** — председатель совещания
- **agenda** — повестка дня (textarea, multi-line)
- **location** — место проведения
- **language** — язык транскрипции (уже реализовано)
- **translation_language** — язык перевода (уже реализовано)

## Сценарий

1. Пользователь открывает протокол (`#/protocols/{id}`)
2. Видит заголовок с `title`, под ним `chair`, `agenda`, `location`
3. Кликает ✏️ рядом с любым полем → поле превращается в input/textarea
4. Редактирует, нажимает Enter (или blur) → PATCH /protocols/{id}
5. Backend обновляет запись в БД, frontend обновляет UI без перезагрузки

## Acceptance Criteria

- [ ] Клик ✏️ превращает поле в input
- [ ] Enter сохраняет, Escape отменяет
- [ ] PATCH /protocols/{id} возвращает 200 + обновлённый протокол
- [ ] UI показывает новые значения без перезагрузки страницы
- [ ] Если PATCH падает — toast.error + rollback к предыдущему значению
- [ ] language/translation_language редактируются через селекторы (E148, E149) — сохраняем

## API

**Существующий endpoint** (E217 — уже используется):
```
PATCH /api/v1/hmp/protocols/{protocol_id}
Content-Type: application/json

{
  "title": "Совещание о планировании Q4",
  "chair": "Иванов И.И.",
  "agenda": "1. Бюджет\n2. Roadmap\n3. Команда",
  "location": "Москва, оф. 404",
  "language": "ru",
  "translation_language": "en"
}
```

**Ответ**: 200 + `ProtocolResponse` с обновлёнными полями.

## Frontend

Кнопка ✏️ рядом с каждым редактируемым полем. Inline-edit через `contenteditable` или input.
