## User Story
**Как** Алексей (P-01),
**я хочу** загрузить локальный аудио/видеофайл (mp3/wav/mp4/mkv),
**чтобы** получить протокол встречи без отправки записи в чужие облака.

## Контекст
- **Процесс:** Этап «Подготовка протокола» — шаг 1 (загрузка файла).
- **Боль персоны:** «SaaS-сервисы сливают данные в облако» → нужен локальный путь.
- **Ограничение:** P-01 хочет, чтобы всё работало офлайн, без утечки.
- **Связь с Vision:** §7.1 Базовое ядро — «Загрузка локального аудио/видеофайла».

## Acceptance Criteria

- **AC-1:** Given я открыл приложение, When я нажимаю «Загрузить файл» и выбираю mp3/wav/mp4/mkv через системный диалог, Then файл сохраняется локально (на диске, не в RAM), в списке появляется новый протокол со статусом «Загружен».

- **AC-2:** Given файл выбран, When начинается обработка, Then я вижу прогресс-бар (0–100%) и оценку оставшегося времени.

- **AC-3:** Given я пытаюсь загрузить файл >2 ГБ, When выбран файл, Then я вижу предупреждение «Файл большой, обработка может занять X минут и потребует до 4 ГБ RAM. Продолжить?» с кнопками «Да» / «Отмена».

- **AC-4:** Given файл успешно загружен, When обработка завершена, Then появляется уведомление «Протокол готов к просмотру» со ссылкой на страницу протокола.

- **AC-5:** Given формат файла не поддерживается (например, .avi или .txt), When выбран файл, Then я вижу сообщение «Формат не поддерживается. Допустимо: mp3, wav, mp4, mkv».

## Технические заметки
- Backend читает файл потоково (chunk ≤8 МБ), сохраняет на диск до начала транскрипции.
- Поддерживаемые форматы: mp3, wav, mp4, mkv (через ffmpeg для декодирования аудио).
- Максимальный размер файла — 10 ГБ (с предупреждением при >2 ГБ).
