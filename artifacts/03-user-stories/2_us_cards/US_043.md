# US-043: GDPR compliance — экспорт и удаление личных данных

| Поле | Значение |
|---|---|
| **ID** | US-043 |
| **Эпик** | EPIC-PRIVACY |
| **Приоритет** | Must |
| **Story Points** | 5 |
| **Персона** | P-01 Алексей (Windows), P-03 Гость (его данные тоже) |
| **Форма** | SettingsPage → PrivacyTab |
| **API** | GET /api/v1/gdpr/export, DELETE /api/v1/gdpr/delete-my-data |

## User Story
**Как** Алексей (P-01) (или участник встречи P-03, чьи данные в протоколе),
**я хочу** иметь возможность экспортировать все свои личные данные (GDPR data portability) и удалить их (right to be forgotten),
**чтобы** соответствовать GDPR / 152-ФЗ и иметь контроль над своими данными.

## Контекст
- **Процесс:** «Управление приватностью» (разовый процесс по запросу).
- **Боль персоны:** «Если участник встречи попросит удалить свои данные из протокола — я должен иметь возможность это сделать, не удаляя весь протокол».
- **Связь с Vision:** §7.1 — GDPR compliance; §8 Risk #5 «Хранение персональных данных без механизма удаления».
- **Допущение:** v1 — single user, multi-tenancy out of scope, но GDPR-принципы применяются к участникам встреч.

## Acceptance Criteria

- **AC-1:** Given я открываю Настройки → Конфиденциальность, When страница загружена, Then я вижу 3 секции:
  - «Экспорт моих данных» (data portability)
  - «Удаление моих данных» (right to be forgotten)
  - «Согласие на обработку» (consent management)

- **AC-2:** Given я нажимаю «Экспорт моих данные», When формируется архив, Then я получаю ZIP-файл `my-data-<YYYY-MM-DD>.zip` со структурой:
  ```
  /user.json           — мой профиль
  /protocols/          — все мои протоколы (метаданные)
  /transcripts/        — все мои транскрипции
  /audio/              — все мои аудиофайлы
  /settings.json       — мои настройки
  /audit-log.csv       — мои действия
  README.md            — описание содержимого
  ```

- **AC-3:** Given я нажал «Удалить мои данные», When я подтверждаю (двойной confirm), Then ВСЕ мои данные удаляются: профиль, протоколы, файлы, настройки, сессии. Приложение сбрасывается к «first run».

- **AC-4:** Given участник встречи (P-03) просит удалить его данные, When я помечаю его имя как «подлежит удалению» в настройках протокола, Then все его реплики заменяются на `[УДАЛЕНО]`, имя оратора удаляется из метаданных, аудио не трогается (это запись встречи).

- **AC-5:** Given я работаю с участниками встреч, When я открываю список ораторов в протоколе, Then я вижу действия: «Переименовать» / «Отметить как анонимного» / «Запросить удаление данных».

- **AC-6:** Given запрос на экспорт, When он обрабатывается, Then я вижу прогресс-бар «Сборка архива...» (большие данные могут занять время).

- **AC-7:** Given у меня 200 протоколов × 2 ч видео (≈50 ГБ), When экспорт, Then архив формируется за ≤10 мин (в фоне).

- **AC-8:** Given я удалил данные, When я пытаюсь войти, Then аккаунт не существует — приложение возвращается к first-run flow (создание нового пользователя).

## Технические заметки
- Соответствие GDPR:
  - Art. 15 (Right of access) → US-043 AC-2 (export)
  - Art. 17 (Right to erasure) → US-043 AC-3 (delete)
  - Art. 20 (Data portability) → US-043 AC-2 (machine-readable JSON)
  - Art. 7 (Consent) → US-043 AC-1 (consent UI)
- Soft delete для участников: `speakers.is_anonymized` флаг + замена текста.
- Hard delete для владельца: TRUNCATE всех таблиц + удаление файлов.
- Аудит (US-042): события `gdpr.exported`, `gdpr.deleted`, `speaker.anonymized`.
