# US-064: Просмотр видео файла в браузере

| Поле | Значение |

## User Story
**Как** Алексей (P-01),
**я хочу** просмотреть загруженное видео/аудио в браузере на странице протокола,
**чтобы** увидеть содержимое во время чтения транскрипции.

## Контекст
- **Процесс:** Просмотр протокола после загрузки.
- **Боль персоны:** «Не могу быстро переключиться на другой файл».
- **Связь с Vision:** §7.1 Базовое ядро — «Аудио/видео плеер».

## Acceptance Criteria

- **AC-1:** Given я открыл протокол с аудио файлом, When отображается страница, Then под метаданными появляется video player с тегом `<video>` или `<audio>`.

- **AC-2:** Given video player загружается, When URL установлен, Then файл начинает воспроизводиться по `/media/protocols/{id}/source.{ext}`.

- **AC-3:** Given файл не существует на диске, When делается запрос, Then backend возвращает 404 с детальным сообщением "Файл не найден на диске".

- **AC-4:** Given файл имеет расширение `.mp4` или `.webm`, When открывается плеер, Then он работает в режиме video (с картинкой).

- **AC-5:** Given файл — только аудио (`.m4a`, `.mp3`, `.wav`), When открывается плеер, Then показывается аудио плеер (без видео).

- **AC-6:** Given есть URL загрузки (`source_url`), When плеер не может найти локальный файл, Then fallback показывает "Файл не найден локально, оригинал: <URL>".

- **AC-7:** Given пользователь нажал Play, When видео воспроизводится, Then есть стандартные контролы (play, pause, scrub, fullscreen).

## Технические заметки
- URL pattern: `GET /api/v1/hmp/media/protocols/{protocol_id}/source.{ext}`
- Backend читает из БД `protocol.audio_file_id → audio_file.file_path`
- Frontend использует Web Component `<video-player>`
- MIME type определяется из `audio_file.mime_type`
- Fallback через `<source>` с URL если локального файла нет
