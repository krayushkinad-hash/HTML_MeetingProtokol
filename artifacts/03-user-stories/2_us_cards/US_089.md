# US-089: Распределённая архитектура — Remote Whisper сервер

**Приоритет**: P1
**Категория**: US (User Story)
**Эпик**: E-013 (Distributed Compute)
**Связанные US**: US-001, US-044 (транскрибация), US-054..066 (settings)
**Зависимости**: UserSetting с новыми полями (E254), PATCH /user-setting

## Описание

Пользователь может подключить **удалённый Whisper-сервер** для транскрибации
вместо локального. Это разгружает CPU компьютера и позволяет использовать
более мощные модели.

## Сценарий (основной)

1. Пользователь открывает **Настройки → Транскрипция**
2. Видит новый блок **"Источник транскрипции"**:
   - ⃝ Локальный Whisper (на этой машине) — default
   - ⃘ Удалённый Whisper-сервер
3. Выбирает "Удалённый" → появляются поля:
   - URL: `http://195.133.77.76:8000`
   - Endpoint: `/transcribe` (default)
4. Нажимает "🔌 Проверить подключение" → проверяется GET `/health`
   - ✅ OK: ok (base) — сервер доступен
   - ❌ недоступен — нужен фикс
5. Нажимает "💾 Сохранить" → PATCH /user-setting сохраняет 3 поля:
   - `whisper_remote_enabled=true`
   - `whisper_remote_url="..."`
   - `whisper_remote_path="/transcribe"`
6. При следующей транскрибации:
   - Frontend проверяет `whisper_remote_enabled`
   - Если `true` — отправляет аудио **напрямую** на remote_url
   - Если `false` — через локальный backend как раньше

## Альтернативный сценарий (fallback)

Если remote сервер недоступен:
- Показывается toast.error
- Пользователь возвращается в настройки
- Меняет источник на "Локальный"
- Сохраняет — продолжает работу

## Архитектура

```
┌─────────────────┐     POST /transcribe     ┌──────────────────┐
│  Frontend       │  ─────────────────────►  │  Remote Whisper  │
│  (Browser)      │  multipart/form-data     │  Server          │
│                 │  {file, model, lang}     │  (VPS, GPU)      │
│  has file,      │                          │                  │
│  sees progress  │  ◄───── JSON ────────── │  returns:        │
└────────┬────────┘  {text, segments}        │  {text, segs[]}  │
         │                                     └──────────────────┘
         │ GET /utterances (save result)
         ▼
┌─────────────────┐
│  Local Backend  │  ←─── utterances save ──│  frontend        │
│  FastAPI +      │       into local DB       │  then reloads    │
│  PostgreSQL     │                           │  transcript      │
└─────────────────┘                           └──────────────────┘
```

## Edge Cases

- **Битый URL**: toast.error "❌ URL недоступен"
- **CORS**: remote сервер отдаёт `Access-Control-Allow-Origin: *`
- **Не сохранилось**: повторно нажать Сохранить
- **CORS не настроен на сервере**: ошибка "Network error"
