# US-042: Audit log — журнал аудита всех значимых действий

| Поле | Значение |
|---|---|
| **ID** | US-042 |
| **Эпик** | EPIC-SEC |
| **Приоритет** | Must |
| **Story Points** | 5 |
| **Персона** | P-01 Алексей (Windows) |
| **Форма** | SettingsPage → AuditLogTab |
| **API** | GET /api/v1/audit-log?from=&to=&action=&user_id= |

## User Story
**Как** Алексей (P-01),
**я хочу** видеть полный журнал всех значимых действий: кто (или какой процесс) и когда входил, загружал файл, удалял протокол, менял настройки,
**чтобы** можно было откатить изменения или найти источник проблемы.

## Контекст
- **Процесс:** «Безопасность и observability» — непрерывный процесс.
- **Боль персоны:** «Что-то почистилось/удалилось — кто? Когда? Хочу лог».
- **Связь с Vision:** §7.1 — «Аудит лог»; §8 Risk #3 «Несанкционированный доступ».
- **KPI:** Все действия user-facing логируются за ≤100 мс.

## Acceptance Criteria

- **AC-1:** Given я открываю Настройки → Audit log, When страница загружена, Then я вижу таблицу событий: «Дата/время», «Пользователь», «Действие», «Объект», «IP», «User-Agent», «Результат (✓/✗)».

- **AC-2:** Given я фильтрую по действию, When я выбираю «Удаление протокола», Then отображаются только события `protocol.deleted` с деталями (какой протокол, кем, когда).

- **AC-3:** Given я фильтрую по диапазону дат, When я выбираю «Прошлая неделя», Then я вижу события только за этот период.

- **AC-4:** Given я нашёл подозрительное событие, When я кликаю на строку, Then открывается детальный просмотр с полным JSON события (включая старые/новые значения для изменений).

- **AC-5:** Given я хочу экспортировать лог, When я нажимаю «Экспорт → CSV» / «JSON», Then скачивается файл для архива / передачи в SIEM.

- **AC-6:** Given событие критическое (failed login, удаление данных, изменение пароля), When оно происходит, Then создаётся также визуальный alert в UI (красная плашка) при следующем входе.

- **AC-7:** Given лог за 2 года, When я открываю страницу, Then загружаются последние 100 событий с пагинацией («Показать ещё»), фильтрация работает по полному индексу.

- **AC-8:** Given я хочу очистить старые логи, When я в настройках выбираю «Очистить логи старше 1 года», Then старые записи удаляются (с подтверждением).

## Технические заметки
- Хранение: `audit_log (id, timestamp, user_id, action, object_type, object_id, ip, user_agent, success, metadata_json)`.
- События, которые логируются:
  - Auth: `auth.login`, `auth.logout`, `auth.password_changed`, `auth.failed_login`
  - Protocols: `protocol.uploaded`, `protocol.transcribed`, `protocol.exported`, `protocol.deleted`, `protocol.shared`
  - Settings: `settings.changed`, `ai.provider_changed`, `telegram.token_changed`
  - AI: `ai.summary_generated`, `ai.task_extracted`, `ai.decision_extracted`
  - Errors: `error.rate_limit`, `error.unauthorized`
- Retention: 2 года (настраивается).
- Индексация: btree по (timestamp, user_id), GIN по `metadata_json` для поиска.
