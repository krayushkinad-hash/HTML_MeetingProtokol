## User Story
**Как** Алексей (P-01),
**я хочу** настроить Telegram-бота прямо из приложения: ввести токен, зарегистрировать свой chat_id, настроить webhook URL, ограничить список разрешённых пользователей,
**чтобы** безопасно использовать Telegram-интерфейс (US-031) без сложной ручной настройки.

## Контекст
- **Процесс:** Настройка приложения (одноразовая операция при подключении Telegram).
- **Боль персоны:** «Хочу Telegram-бот, но не хочу лезть в консоль, редактировать .env, регистрировать webhook через curl. Хочу всё через UI».
- **Связь с Vision:** §7.4 — Telegram бот setup; §7a — UI конфигурация.
- **KPI:** Время setup ≤5 мин (vs 30 мин вручную).

## Acceptance Criteria

- **AC-1:** Given я открываю Настройки → Telegram, When страница загружена, Then я вижу 3 секции:
  - «Bot Token» — поле для токена от @BotFather + кнопка «Проверить подключение» (US-067)
  - «Allowed Users» — список chat_id, которым разрешено пользоваться ботом
  - «Webhook» — автоматически сгенерированный URL + кнопка «Зарегистрировать webhook»

- **AC-2:** Given я ввёл токен и нажал «Проверить подключение», When backend делает `getMe`, Then я вижу карточку с именем бота, username, ID — зелёная плашка «Подключение успешно».

- **AC-3:** Given бот подключён, When я открываю бота в Telegram и пишу ему `/start`, Then бот отвечает «Ваш chat_id: 123456789. Сообщите его для регистрации или нажмите кнопку в приложении».

- **AC-4:** Given я вижу chat_id в Telegram, When я ввожу его в поле «Add chat_id» в приложении и нажимаю «+», Then chat_id добавляется в список разрешённых, этому пользователю становится доступен бот.

- **AC-5:** Given я нажал «Зарегистрировать webhook», When backend делает `setWebhook`, Then я вижу «Webhook зарегистрирован: https://localhost:8000/api/v1/telegram/webhook» + дата/время последней регистрации.

- **AC-6:** Given я хочу запретить пользователя, When я нажимаю «🗑 Удалить» рядом с chat_id, Then chat_id удаляется из whitelist, бот перестаёт отвечать этому пользователю.

- **AC-7:** Given я ввёл невалидный токен (формат неверный), When я нажимаю «Проверить», Then я вижу красную плашку «Невалидный токен. Формат: <числа>:<буквы-цифры>».

- **AC-8:** Given токен уже сохранён, When я редактирую поле, Then новый токен применяется только после явного «Сохранить» (с подтверждением), webhook перерегистрируется.

## Технические заметки
- Хранение токена: зашифрован Fernet (как SMTP-пароль в US-034).
- Whitelist: `telegram_allowed_users (chat_id, username, added_at, last_seen_at)`.
- Webhook secret token: генерируется автоматически, хранится в env, проверяется в заголовке `X-Telegram-Bot-Api-Secret-Token`.
- HTTPS для webhook: обязателен (Telegram не принимает HTTP). Для localhost используется туннель (ngrok/localtunnel) — НЕ в скоупе MVP, требует ручной настройки.
- Аудит (US-042): создание/удаление chat_id, изменение токена.
