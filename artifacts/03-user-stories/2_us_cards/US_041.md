# US-041: API rate limiting — защита от злоупотреблений

| Поле | Значение |
|---|---|
| **ID** | US-041 |
| **Эпик** | EPIC-SEC |
| **Приоритет** | Must |
| **Story Points** | 3 |
| **Персона** | P-01 Алексей (Windows), защита от случайных/злонамеренных клиентов |
| **Форма** | — (middleware) |
| **API** | Все endpoints (через middleware) |

## User Story
**Как** Алексей (P-01) (как администратор локального приложения),
**я хочу** чтобы все API endpoints имели rate limiting (например, 100 запросов/мин с одного IP),
**чтобы** защитить backend от случайных DDoS, runaway-скриптов и ошибок клиента, приводящих к шторму запросов.

## Контекст
- **Процесс:** Защита инфраструктуры (непрерывный процесс).
- **Боль персоны:** «Случайный баг в клиенте может завалить backend тысячами запросов. Rate limiting защитит».
- **Связь с Vision:** §7.1 — «Базовая безопасность»; §8 Risk #2 «Backend overload».
- **KPI:** Backend выдерживает 100 RPS без деградации.

## Acceptance Criteria

- **AC-1:** Given я делаю 100 запросов за 1 минуту с одного IP, When превышаю лимит, Then следующий запрос возвращает HTTP 429 Too Many Requests с заголовком `Retry-After: 60` и телом `{"error": "rate_limit_exceeded", "limit": 100, "window": "1m"}`.

- **AC-2:** Given я превысил лимит, When я вижу UI, Then появляется toast «Слишком много запросов. Подождите 60 секунд».

- **AC-3:** Given я делаю запросы с разных IP (loopback, localhost, 127.0.0.1, ::1), When каждый IP имеет свой bucket, Then лимит применяется per-IP (не глобально).

- **AC-4:** Given для разных endpoints разные лимиты, When я делаю много запросов, Then:
  - `/transcribe/*` — 10 RPS (тяжёлые операции)
  - `/export/*` — 5 RPS
  - `/search/*` — 30 RPS
  - Остальные — 100 RPS

- **AC-5:** Given я аутентифицирован, When я делаю много запросов, Then лимит применяется per-user_id (а не per-IP), что позволяет мне работать с нескольких устройств.

- **AC-6:** Given backend перезапустился, When state rate limiter сбросился, Then лимиты начинают считаться заново (in-memory state).

- **AC-7:** Given я в Astra Linux офлайн (P-02), When я делаю запросы к localhost, Then rate limiting не блокирует нормальную работу (лимиты достаточно мягкие для локального использования).

- **AC-8:** Given я — администратор, When я хочу отключить rate limiting (для тестов), Then я могу установить `RATE_LIMITING_ENABLED=false` в `.env`.

## Технические заметки
- Библиотека: `slowapi` (FastAPI-friendly) или `fastapi-limiter` (с Redis).
- Алгоритм: token bucket или sliding window.
- Хранение счётчиков: in-memory (по умолчанию) или Redis (для multi-instance).
- Whitelist: localhost / 127.0.0.1 / 192.168.0.0/16 (для P-02 в домашней сети) — без лимита.
- Конфиг: `RATE_LIMIT_DEFAULT=100/min`, `RATE_LIMIT_TRANSCRIBE=10/s`, и т.д.
- Логирование: каждое превышение → audit log (US-042).
