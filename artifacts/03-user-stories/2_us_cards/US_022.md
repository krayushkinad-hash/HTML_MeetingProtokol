# US-022: Генерация структурированного саммари протокола через LLM

## User Story
**Как** Алексей (P-01),
**я хочу** после транскрипции получить автоматически сгенерированное саммари встречи: темы, ключевые тезисы, итоги по каждому обсуждению,
**чтобы** не читать 2-часовую транскрипцию, чтобы понять, что было на встрече.

## Контекст
- **Процесс:** Этап «Подготовка протокола» — шаг «Генерация саммари» (после транскрипции + диаризации).
- **Боль персоны:** «Прочитать 2-часовую транскрипцию = ещё 30 мин. Хочу саммари за 30 сек чтения».
- **KPI Vision:** 😊 Quality — ROUGE-L vs ручной эталон ≥ 0.5.
- **Связь с Vision:** §7.1 — «Саммари через LLM»; §6 Цель #6 «AI-фичи».

## Acceptance Criteria

- **AC-1:** Given транскрипция завершена, When я нажимаю «Сгенерировать саммари», Then LLM получает текст транскрипции (чанками ≤3000 символов с overlap 200) и возвращает структурированный JSON:
  ```json
  {
    "title": "Планёрка Q4 — обсуждение roadmap",
    "topics": [
      {"name": "Релиз 2.3", "summary": "Решено выпустить 15 ноября. Иван отвечает за код, Мария — за тесты."},
      {"name": "Бюджет", "summary": "Урезали маркетинговый бюджет на 20%."}
    ],
    "key_points": ["Перенесли дедлайн релиза", "Наняли нового разработчика"]
  }
  ```

- **AC-2:** Given саммари готово, When я открываю вкладку «Саммари» в протоколе, Then я вижу его в виде структурированного документа: заголовок, список тем (раскрывающиеся карточки), ключевые пункты (bullet list).

- **AC-3:** Given саммари содержит упоминание реплики, When я кликаю на цитату («Иван сказал...»), Then открывается соответствующий момент в транскрипции (таймкод).

- **AC-4:** Given LLM-сервис недоступен, When я пытаюсь сгенерировать саммари, Then я вижу «Саммари недоступно. Проверьте настройки AI-провайдера» (см. US-066).

- **AC-5:** Given саммари уже было сгенерировано, When я нажимаю «Перегенерировать», Then старое саммари архивируется, создаётся новое, можно сравнить (A/B diff).

- **AC-6:** Given я в Astra Linux офлайн, When я пытаюсь сгенерировать саммари, Then используется локальный Ollama (US-040) или функция отключается с понятным сообщением.

## Технические заметки
- Промпт для LLM включает инструкцию формата JSON + ролевую установку «Ты — ассистент, составляющий протоколы совещаний».
- Двухпроходный режим: первый проход — обзор тем, второй — детализация по каждой теме (Map-Reduce).
- Модели: primary — Hermes Agent (US-039), fallback — GigaChat (US-038), offline — Ollama (US-040).
- Кеширование: один раз сгенерированное саммари хранится в `protocols.summary_json`.
