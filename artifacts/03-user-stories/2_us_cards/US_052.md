# US-052: Мягкое удаление протокола

| Поле | Значение |
|---|---|
| **ID** | US-052 |
| **Эпик** | EPIC-LIFECYCLE |
| **Приоритет** | Must |
| **Story Points** | 2 |
| **Персона** | P-01 Алексей (Windows) |
| **Форма** | ProtocolCard (context menu) |
| **API** | DELETE /api/v1/hmp/protocols/{id} |

## User Story
**Как** Алексей (P-01),
**я хочу** иметь возможность пометить протокол как удалённый (soft delete),
**чтобы** убрать его из основных списков и поиска, но сохранить возможность восстановления.

## Контекст
> **Note:** US-052 (soft delete) упразднён в пользу US-053 (hard delete).
> Один простой confirm() диалог → hard delete всегда.
- **Процесс:** Управление жизненным циклом протокола.
- **Боль персоны:** Ошибочно нажал «удалить» — потерял данные без возможности восстановить.
- **Связь с Vision:** §7.1 Базовое ядро — «Локальная работа с данными».

## Acceptance Criteria

- **AC-1:** Given я на странице протокола, When я нажимаю кнопку «🗑 Удалить» и ввожу «SOFT», Then протокол помечается как удалённый (deleted_at = now()) и исчезает из списка.

- **AC-2:** Given протокол помечен как удалённый, When я открываю страницу «Все протоколы», Then он не отображается в основном списке.

- **AC-3:** Given протокол помечен как удалённый, When я делаю запрос к API с `include_deleted=true`, Then протокол возвращается со статусом «deleted».

- **AC-4:** Given протокол помечен как удалённый, When я обращаюсь к его `/media/...` файлу, Then файл всё ещё доступен (физически не удалён).

- **AC-5:** Given я подтвердил удаление, When я перехожу на главную, Then Toast «Протокол помечен как удалённый» и редирект на список.

## Технические заметки
- Soft delete = установка `deleted_at` timestamp
- Запросы автоматически фильтруют `WHERE deleted_at IS NULL`
- Отдельный endpoint `GET /protocols/{id}/deleted` для просмотра удалённых
