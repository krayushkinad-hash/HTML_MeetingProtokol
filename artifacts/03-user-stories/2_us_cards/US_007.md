# US-007: Автоматическая диаризация ораторов с DER ≤20%

## User Story
**Как** Алексей (P-01),
**я хочу**, чтобы автодиаризация определила ораторов по голосовому профилю с DER ≤20%,
**чтобы** не размечать спикеров вручную после каждой встречи.

## Контекст
- **Процесс:** Этап «Подготовка протокола» — шаг 3 (диаризация).
- **Боль персоны:** «На встрече 5 человек — вручную расставлять ораторов по репликам = 30 мин мучений».
- **Боль персоны P-03:** «Хочу быть уверенным, что реплики не перепутают и не припишут мне чужие слова».
- **KPI Vision:** 😊 Quality DER ≤20%.
- **Связь с Vision:** §7.1 — «Автоматическая диаризация (бывший stretch → MVP)».

## Acceptance Criteria

- **AC-1:** Given транскрипция завершена, When запускается автодиаризация, Then каждой реплике присваивается метка SPEAKER_NN (NN — номер оратора).

- **AC-2:** Given на встрече 2–5 ораторов, When модель обрабатывает аудио, Then DER ≤20% на тестовой выборке (метрика по pyannote.metrics).

- **AC-3:** Given диаризация завершена, When я открываю протокол, Then я вижу реплики, сгруппированные по ораторам (SPEAKER_00 говорил с 0:32 по 1:15, SPEAKER_01 — с 1:18 по 2:00, ...).

- **AC-4:** Given диаризация прошла, When я открываю протокол, Then доступна кнопка «Переименовать ораторов» — после моей ручной разметки модель запоминает голосовой профиль для будущих встреч (см. US-008).

## Технические заметки
- Модель: pyannote.audio 3.x (Speaker Diarization Pipeline).
- Требует GPU ≥4 ГБ VRAM (или CPU-only с пониженной скоростью).
- HuggingFace token для доступа к модели (ввести при первом запуске).
- Должна работать в связке с Whisper (speaker embeddings передаются из диаризации в финальную транскрипцию).
