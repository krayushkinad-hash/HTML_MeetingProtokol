## User Story
**Как** Алексей (P-01),
**я хочу** во время онлайн-встречи видеть живую транскрипцию: по мере того, как участники говорят, реплики появляются в реальном времени с таймкодами,
**чтобы** не вести заметки вручную, а участвовать в разговоре и иметь готовый протокол сразу после встречи.

## Контекст
- **Процесс:** «Онлайн-встреча в Яндекс Телемост» — параллельный процесс.
- **Боль персоны:** «Во время встречи не успеваю конспектировать — половина решений забывается».
- **KPI Vision:** ⚡ Performance — Latency ≤3 сек от реплики.
- **Связь с Vision:** §7.1 — «Live Mode: живая транскрипция»; §6 Цель #4 «Интегрировать Яндекс Телемост».

## Acceptance Criteria

- **AC-1:** Given я подключился к встрече, When я нажимаю «Начать запись + транскрипцию», Then:
  - Аудио захватывается через `getUserMedia` (микрофон) или `getDisplayMedia` (системный звук)
  - WebSocket отправляет чанки по 0.5 сек на backend
  - Backend транскрибирует через Whisper streaming
  - Результат возвращается через WebSocket и появляется в UI

- **AC-2:** Given идёт встреча, When кто-то говорит ≥1 сек, Then через ≤3 сек в правой панели появляется реплика с таймкодом (от начала встречи) и текстом.

- **AC-3:** Given реплика появилась, When идёт поток, Then старые реплики автоматически прокручиваются, активная реплика подсвечена цветом (US-012).

- **AC-4:** Given встреча завершилась, When я нажимаю «Остановить запись», Then:
  - Аудио сохраняется в файл
  - Финальная транскрипция собирается из чанков
  - Диаризация запускается
  - Создаётся новый протокол со статусом «Загружен» → «Транскрибируется»

- **AC-5:** Given WebSocket оборвался (потеря сети), When я пытаюсь продолжить, Then появляется «Соединение потеряно. Переподключение...», через 5 сек — авто-reconnect, чанки за время разрыва не теряются (буфер на клиенте).

- **AC-6:** Given я в режиме live, When я хочу сделать пометку, я нажимаю Ctrl+Shift+T (см. US-009), и текущая реплика помечается ⭐.

- **AC-7:** Given встреча идёт >3 часов, When лимит, Then появляется предупреждение «Длинная встреча. Рекомендуется разделить на 2 протокола для стабильности».

## Технические заметки
- WebSocket: `wss://localhost:8000/ws/transcribe/live`.
- Чанкинг: 0.5 сек аудио (16 kHz mono, int16) → ~16 КБ.
- Backend: Whisper streaming mode (или faster-whisper с VAD).
- Буфер на клиенте: последние 30 сек аудио для reconnect.
- Latency target: streaming chunk 0.5 сек → inference 1.5–3 сек → UI update.
- См. также: US-019 (три панели), US-009 (теги в live), US-046/US-047 (скриншоты).
