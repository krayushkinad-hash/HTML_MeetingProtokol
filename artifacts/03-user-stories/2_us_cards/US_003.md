# US-003: Diarization review — ручная правка и объединение ораторов через UI

| Поле | Значение |
|---|---|
| **ID** | US-003 |
| **Эпик** | EPIC-TRANS |
| **Приоритет** | Must |
| **Story Points** | 5 |
| **Персона** | P-01 Алексей (Windows), P-03 Гость |
| **Форма** | ProtocolView → SpeakersTab |
| **API** | PATCH /api/v1/transcribe/speakers/{protocol_id} |

## User Story
**Как** Алексей (P-01),
**я хочу** через UI переименовать ораторов, объединить двух ораторов в одного (split-merge) и пометить «это не наш голос — удалить»,
**чтобы** исправить ошибки автодиаризации и получить корректное распределение реплик.

## Контекст
- **Процесс:** Этап «Подготовка протокола» — шаг 3.5 (корректировка диаризации после US-007).
- **Боль персоны:** «На встрече 5 человек — автодиаризация разделила одного на SPEAKER_02 + SPEAKER_04. Хочу одной кнопкой объединить».
- **Боль P-03:** «Если реплики ошибочно приписаны мне — я должен иметь возможность попросить переименовать и пометить правильно».
- **Связь с Vision:** §7.1 — «Идентификация ораторов вручную (для MVP)»; §5 Преимущество #5 «Идентификация ораторов».

## Acceptance Criteria

- **AC-1:** Given диаризация завершена, When я открываю вкладку «Ораторы» в протоколе, Then я вижу список уникальных ораторов (SPEAKER_00, SPEAKER_01, …), для каждого — количество реплик и общая длительность речи.

- **AC-2:** Given я выбрал оратора, When я нажимаю «Переименовать», Then открывается inline-инпут, я ввожу имя (например, «Алексей» / «Мария»), нажимаю Enter, имя сохраняется в БД и применяется ко всем репликам этого оратора.

- **AC-3:** Given я хочу объединить двух ораторов, When я выбираю чекбоксы у SPEAKER_02 и SPEAKER_04 и нажимаю «Объединить», Then появляется диалог «Объединить SPEAKER_02 и SPEAKER_04? Имя будет: ___», после подтверждения все реплики SPEAKER_04 переназначаются на SPEAKER_02, а SPEAKER_04 удаляется.

- **AC-4:** Given реплика ошибочно приписана чужому оратору, When я кликаю на реплику в транскрипции и в выпадающем меню выбираю другого оратора, Then реплика переназначается, изменения сохраняются по кнопке «Сохранить» или автоматически (debounce 2 сек).

- **AC-5:** Given я внёс правки, When я перезагружаю страницу, Then мои переименования и объединения сохраняются (в БД, не в локальной памяти).

- **AC-6:** Given я правил ораторов несколько раз, When я нажимаю «Отменить последнее изменение» (Undo, Ctrl+Z), Then предыдущее состояние восстанавливается.

## Технические заметки
- Backend: `PATCH /api/v1/transcribe/speakers/{protocol_id}` принимает массив операций `{op: "rename"|"merge"|"reassign", ...}`.
- Хранение имён в таблице `speakers (id, protocol_id, label, display_name, voice_embedding)`.
- Voice embeddings (от pyannote) сохраняются для повторного использования в будущих встречах (см. US-007 AC-4).
- Frontend: использует optimistic updates + rollback при ошибке API.
- Логирование операций в audit log (см. US-042).
