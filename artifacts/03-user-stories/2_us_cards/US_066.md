# US-066: Улучшенный интерфейс AI провайдера

| Поле | Значение |
|---|---|
| **ID** | US-066 |
| **Эпик** | EPIC-SETTINGS |
| **Приоритет** | Should |
| **Story Points** | 3 |
| **Персона** | P-01 Алексей (Windows) |

| **API** | GET/PATCH /api/v1/hmp/user-setting |

## User Story
**Как** Алексей (P-01),
**я хочу** настраивать каждый AI провайдер отдельно с визуальной индикацией статуса,
**чтобы** не вводить префиксы вручную и сразу видеть какие провайдеры настроены, а какие нет.

## Контекст
- **Процесс:** Настройка AI функций приложения.
- **Боль персоны:** «HERMES_API_KEY=, GIGACHAT_API_KEY=... — помнить префиксы неудобно».
- **Связь с Vision:** §7.5 UX — современный отзывчивый интерфейс.

## Acceptance Criteria

- **AC-1:** Given я открыл Настройки → AI провайдер, When страница загружена, Then 3 карточки провайдеров (Hermes, GigaChat, Ollama) с полями ввода API ключа.

- **AC-2:** Given каждая карточка, When я смотрю на неё, Then вижу статус:
  - **● Настроен** (зелёный) — ключ введён
  - **○ Не настроен** (серый) — ключ пустой

- **AC-3:** Given статус "Не настроен", When я ввожу хотя бы 1 символ, Then статус мгновенно меняется на "Настроен" (real-time).

- **AC-4:** Given я ввёл только значение (без префикса), When я сохраняю, Then система сама добавляет правильный префикс:
  - Hermes → `HERMES_API_KEY=value`
  - GigaChat → `GIGACHAT_API_KEY=value`
  - Ollama → `OLLAMA_URL=value`

- **AC-5:** Given есть 3 провайдера, When я настраиваю только Hermes (как основной), Then саммари работает через Hermes, а GigaChat и Ollama отображаются как "Не настроен".

- **AC-6:** Given я нажал "Проверить подключение", When запрос отправляется, Then показывается результат (успех/ошибка) с зелёной или красной подсветкой.

- **AC-7:** Given вкладка "Основной/Резервный провайдер", When я меняю провайдера, Then введённые ключи сохраняются.

- **AC-8:** Given заполнено несколько полей, When я нажимаю "Сохранить", Then все ключи добавляются в `api_keys` с правильными префиксами и сохраняются на backend.

## Технические заметки

- Frontend: `parseApiKeys()` разбирает `KEY=value` строки в объект `{hermes, gigachat, local_ollama}`
- Frontend: `buildApiKeysString()` собирает обратно `KEY=value` формат с префиксами
- Используется общий фоновый цвет `var(--bg-secondary)`
- Real-time обновление статуса через `input` event listener
- Кнопка "Проверить подключение" вызывает `api.summarize({test: true})`
