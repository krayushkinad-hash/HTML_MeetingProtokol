## User Story
**Как** Алексей (P-01),
**я хочу** видеть полный путь к файлу видео на диске на странице протокола,
**чтобы** найти его вручную, открыть в другой программе или скопировать.

## Контекст
- **Процесс:** Навигация по протоколу.
- **Боль персоны:** «Где лежит сам файл, нужно листать диск».
- **Связь с Vision:** §7.1 Базовое ядро — «Локальная работа с файлами».

## Acceptance Criteria

- **AC-1:** Given я открыл протокол с видео файлом, When отображается страница, Then под заголовком видно имя файла, размер и **полный путь к файлу на диске**.

- **AC-2:** Given путь длинный, When он отображается, Then он сокращён до `.../folder/file.ext` через `formatPath()`, но полный путь доступен в tooltip.

- **AC-3:** Given пользователь нажал кнопку "📋 Скопировать", When выполняется копирование, Then полный путь попадает в буфер обмена и Toast показывает "Путь скопирован".

- **AC-4:** Given backend недоступен, When `navigator.clipboard` не работает, Then показывается предупреждение "Не удалось скопировать".

- **AC-5:** Given у протокола нет audio_file, When отображается страница, Then секция с информацией о файле не появляется.

## Технические заметки
- Backend `AudioFileResponse` расширен полем `file_path: str | None`
- Frontend использует `formatPath()` для сокращения длинных путей
- `navigator.clipboard.writeText()` для копирования
- `title` атрибут на элементе содержит полный путь
