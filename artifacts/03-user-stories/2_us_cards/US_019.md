## User Story
**Как** Алексей (P-01),
**я хочу** во время встречи видеть три панели: видео участников, основные темы, живая транскрипция реплик,
**чтобы** участвовать в разговоре, а не конспектировать.

## Контекст
- **Процесс:** «Онлайн-встреча в Яндекс Телемост» — параллельный процесс (см. business-process-modeler).
- **Боль персоны:** «Во время встречи не успеваю конспектировать — теряю нить разговора».
- **Связь с Vision:** §7.1 «Онлайн-режим» — «Живая транскрипция во время встречи».

## Acceptance Criteria

- **AC-1:** Given я подключился к Яндекс Телемост по ссылке, When я нажимаю «Включить режим протокола», Then интерфейс разделяется на 3 панели:
  - Левая: видео участников (iframe Телемоста)
  - Центральная: список тем встречи (автоматически выделяемые ключевые фразы)
  - Правая: живая транскрипция с таймкодами и активной репликой (выделена цветом)

- **AC-2:** Given идёт встреча, When кто-то говорит, Then через ≤3 сек в правой панели появляется реплика с таймкодом, текстом и меткой оратора.

- **AC-3:** Given реплика появилась в транскрипции, When я навожу на неё, Then показывается кнопка «Пометить важное» ⭐.

- **AC-4:** Given я пометил реплику как важную, When встреча закончилась, Then в итоговом протоколе эти реплики выделены визуально (жирный, рамка или другой стиль).

- **AC-5:** Given в транскрипции накопились реплики, When я ищу по ключевому слову в правой панели, Then фильтруются только реплики с этим словом (без перезагрузки страницы).

## Технические заметки
- WebSocket-соединение с backend для потока транскрипции (чанки аудио → сервер → текст).
- Захват аудио из iframe Телемоста: ограничен CORS — нужно использовать getUserMedia + микрофон системы ИЛИ отдельный Electron-wrapper.
- Альтернатива: запись системного звука через `navigator.mediaDevices.getDisplayMedia({audio: true})`.
- Latency: streaming chunk 0.5 сек → модель даёт результат за 1.5–3 сек → WebSocket → UI.
