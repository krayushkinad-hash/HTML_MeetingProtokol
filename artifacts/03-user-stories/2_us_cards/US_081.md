# US-081 — Потоковая запись реплик при транскрибации

**Epic:** US-005 — Транскрипция
**Priority:** High
**Status:** Done (2026-09-22)
**Effort:** 3 SP
**Refs:** E131, E132

## User Story

> Как **менеджер проекта**, записывающий часовые совещания,
> я хочу **видеть текст реплик в реальном времени во время обработки**,
> чтобы **не ждать час глядя на 0 реплик и скучать**,
> а видеть как Whisper распознаёт по мере генерации.

## Acceptance Criteria

- [x] Сегменты кладутся в thread-safe `queue.Queue` из worker thread
- [x] `_persist_utterances_loop` в main event loop забирает batch каждые 2 сек
- [x] Финальный flush остатка очереди при завершении транскрибации
- [x] `segments_count` в `/transcribe/progress/{task_id}` = реальное число в БД
- [x] Frontend polling подтягивает новые реплики при росте `segments_count`
- [x] При повторной транскрибации старые utterance удаляются (перезапись)
- [x] utterances_task дожидается в finally (timeout 15 сек на финальный flush)
- [x] CancelledError корректно останавливает loop

## Technical Design

### Component Flow

```
┌──────────────────────────────────────────────────────────────┐
│  Whisper worker thread (asyncio.to_thread)                  │
│  _run_transcribe_eager()                                    │
│     │                                                       │
│     ├─→ segments_list  (в памяти для финального summary)    │
│     └─→ queue.Queue.put({start, end, text})  ←E131         │
└────────────────────────┬─────────────────────────────────────┘
                         │
                         ▼
                  ┌─────────────────┐
                  │   queue.Queue   │  ← thread-safe
                  │  (FIFO buffer)  │
                  └────────┬────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│  _persist_utterances_loop (asyncio.Task in main event loop)  │
│                                                              │
│  while not stop_event.is_set():                              │
│     1. drain queue → batch[]                                │
│     2. INSERT INTO utterance (start_sec, end_sec, text)      │
│     3. await wait(stop_event, timeout=2.0)                  │
│                                                              │
│  # Финальный flush после finally:                            │
│  drain queue → INSERT (остаток)                              │
└────────────────────────┬─────────────────────────────────────┘
                         │
                         ▼
                  ┌─────────────────┐
                  │  PostgreSQL     │
                  │  utterance      │
                  └────────┬────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│  Frontend polling (setInterval 2 sec)                        │
│                                                              │
│  GET /progress/{task_id} → {segments_count: 12}             │
│  if segCount > lastCount:                                   │
│     GET /utterances?protocol_id=X → list                    │
│     render panel-transcript.innerHTML                        │
└──────────────────────────────────────────────────────────────┘
```

### Key Design Decisions

| Решение | Почему |
|---|---|
| `queue.Queue`, не `queue.Queue` из async | Worker thread → основной loop; нужна thread-safe синхронизация |
| Flush каждые 2 сек, не каждый сегмент | Компромисс: latency 2 сек vs нагрузка на БД (INSERT каждые 30ms) |
| `utterances_task` await в finally с timeout=15 | Гарантирует flush остатка даже если persist_task долгий |
| Удалять старые utterances перед стартом | Перезапись при повторной транскрибации |
| `segments_count` через `count(*)` | Реальное число из БД (не in-memory счётчик) |
