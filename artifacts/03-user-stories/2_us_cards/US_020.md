# US-020: Progress-bar для длительных операций

| Поле | Значение |
|---|---|
| **ID** | US-020 |
| **Эпик** | EPIC-UX |
| **Приоритет** | Must |
| **Story Points** | 3 |
| **Персона** | P-01 Алексей (Windows) |
| **Форма** | ProgressBar (общий компонент) |
| **API** | WebSocket /ws/progress/{task_id} |

## User Story
**Как** Алексей (P-01),
**я хочу** для всех длительных операций (транскрипция, диаризация, генерация саммари, экспорт DOCX) видеть единый progress-bar с процентом, оценкой оставшегося времени и текущим этапом,
**чтобы** понимать, сколько ещё ждать, и не думать, что приложение зависло.

## Контекст
- **Процесс:** Все этапы «Подготовка протокола» + экспорт.
- **Боль персоны:** «Загрузил 2-часовую запись — прошло 5 минут, не понятно, сколько ещё. Думаю, что зависло».
- **KPI Vision:** 📊 Engagement — «Время от загрузки до готового DOCX ≤ 5 мин на 1 час аудио».
- **Связь с Vision:** §7.1 — UX обратной связи для длительных операций.

## Acceptance Criteria

- **AC-1:** Given идёт длительная операция (транскрипция, диаризация, саммари, DOCX-экспорт), When она в процессе, Then я вижу progress-bar с:
  - Процент выполнения (0–100%)
  - Текущий этап («Транскрипция чанка 5 из 12» / «Диаризация 50%» / «Генерация саммари…»)
  - Оценка оставшегося времени (ETA: ~2 мин)

- **AC-2:** Given операция завершена, When она успешна, Then progress-bar заменяется на toast «Готово» с зелёной иконкой, через 3 сек исчезает.

- **AC-3:** Given операция упала, When происходит ошибка, Then progress-bar становится красным с сообщением «Ошибка: <details>» и кнопкой «Повторить».

- **AC-4:** Given идёт несколько операций параллельно (например, транскрипция + диаризация для разных протоколов), When я смотрю на UI, Then я вижу несколько progress-bar в отдельной панели «Задачи» внизу страницы.

- **AC-5:** Given я навожу на progress-bar, When я вижу детали, Then появляется tooltip с детальной информацией (скорость, расход памяти, чанк).

- **AC-6:** Given операция идёт, When я переключаюсь на другую вкладку, Then progress-bar остаётся видимым (badge на иконке вкладки браузера и в navbar приложения).

## Технические заметки
- Backend: каждая фоновая задача публикует прогресс в Redis pub/sub или через WebSocket.
- Frontend: общий компонент `<progress-bar>` с слотами для этапов.
- Оценка ETA: линейная экстраполяция на основе уже обработанных чанков.
- Цвета: синий (в процессе), зелёный (готово), красный (ошибка) — Design System US-068.
