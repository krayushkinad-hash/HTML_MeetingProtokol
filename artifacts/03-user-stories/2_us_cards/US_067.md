# US-067: Проверка связи с Telegram ботом

| Поле | Значение |
|---|---|
| **ID** | US-067 |
| **Эпик** | EPIC-TELEGRAM |
| **Приоритет** | Must |
| **Story Points** | 3 |
| **Персона** | P-01 Алексей (Windows) |
| **Форма** | SettingsPage → BotTab (кнопка "Проверить подключение") |
| **API** | POST /api/v1/hmp/bot/test-connection |

## User Story
**Как** Алексей (P-01),
**я хочу** проверить правильность Telegram bot токена и доступность бота прямо из настроек,
**чтобы** убедиться что бот работает до того как я начну им пользоваться.

## Контекст
- **Процесс:** Настройка Telegram бота для AI-прокси.
- **Боль персоны:** «Ввёл токен, перезапустил backend — но не знаю работает ли. Хочу проверить прямо сейчас».
- **Связь с Vision:** §7.4 Telegram бот, §7a Test connection UI.

## Acceptance Criteria

- **AC-1:** Given я на вкладке "Telegram" в Настройках, When я нажимаю кнопку "Проверить подключение", Then отправляется POST запрос к бэкенду.

- **AC-2:** Given backend получил валидный токен, When бэкенд делает запрос к Telegram API `getMe`, Then возвращается 200 OK с информацией о боте (id, name, username).

- **AC-3:** Given UI получил успешный ответ, When он показывает результат, Then видна зелёная плашка с:
  - Иконка бот: 🤖
  - Имя бота
  - Username с префиксом @
  - ID бота (число)
  - Может отвечать на сообщения: Да

- **AC-4:** Given введённый токен невалидный, When делается запрос к Telegram, Then UI показывает красную плашку с:
  - Иконка ❌
  - Текст "Не удалось подключиться"
  - Описание ошибки от Telegram
  - Подсказку как исправить

- **AC-5:** Given backend недоступен, When я нажимаю кнопку, Then UI показывает жёлтую плашку "Backend не отвечает".

- **AC-6:** Given я подождал 30 секунд и ответа нет, Then UI показывает ошибку таймаута "Не отвечает слишком долго".

- **AC-7:** Given проверка успешна, When я редактирую токен, Then плашка автоматически скрывается чтобы не вводила в заблуждение.

## Технические заметки
- Backend: POST /api/v1/hmp/bot/test-connection с телом `{bot_token: "..."}`
- Backend использует httpx или requests для вызова Telegram `https://api.telegram.org/bot<TOKEN>/getMe`
- Timeout: 10 секунд
- НЕ сохранять токен в БД до явного сохранения пользователем
- НЕ отправлять токен в логи

## Связанные артефакты

- US-037: Регистрация Telegram пользователя (US-068)
- NFR: §5.7 Внешние API (timeouts)
- Vision §7a

## Реализация

### Backend (TelegramClient)
- POST /api/v1/hmp/bot/test-connection
- Использует httpx.AsyncClient с timeout=10
- Возвращает: {ok: bool, bot_info: {...}, error: "..."}

### Frontend
- Settings → BotTab → кнопка "🔌 Проверить подключение"
- Loading state во время запроса
- Success: зелёная карточка с информацией о боте
- Error: красная карточка с описанием
- Timeou: жёлтая карточка

## Tests
- Mock Telegram API → проверить успешный flow
- Невалидный токен → ошибка 401
- Backend timeout → жёлтая плашка
