# US-046: Автоматический capture скриншотов экрана (через интервал)

| Поле | Значение |
|---|---|
| **ID** | US-046 |
| **Эпик** | EPIC-SCREENS |
| **Приоритет** | Should |
| **Story Points** | 5 |
| **Персона** | P-01 Алексей (Windows) |
| **Форма** | LiveMode → ScreenshotsPanel |
| **API** | POST /api/v1/live/screenshots (multipart upload) |

## User Story
**Как** Алексей (P-01),
**я хочу** во время онлайн-встречи автоматически делать скриншот экрана через заданный интервал (например, каждые 60 секунд) или при смене содержимого экрана (scene change detection),
**чтобы** к протоколу привязать визуальный контекст того, что показывалось на экране демонстранта.

## Контекст
- **Процесс:** «Онлайн-встреча в Яндекс Телемост» — параллельный процесс.
- **Боль персоны:** «На встрече обсуждали код/схему — хочу в протоколе видеть, ЧТО именно показывали, а не только текст "обсудили миграцию"».
- **Связь с Vision:** §7.1 — «Авто-capture скриншотов»; §5 Преимущество #6 «Скриншоты экрана».
- **Зависимость:** US-030 (Live Mode), US-019 (3 панели).

## Acceptance Criteria

- **AC-1:** Given я в live mode, When я нажимаю «▶ Запустить авто-capture», Then начинается захват экрана через `getDisplayMedia` (выбор окна/экрана демонстранта) каждые N секунд (настраивается, по умолчанию 60 сек).

- **AC-2:** Given захват включён, When проходит 60 сек, Then backend получает скриншот (PNG), сохраняет в `~/.html_mp/protocols/<id>/screenshots/<HH-MM-SS>.png`, появляется в панели «Скриншоты» с таймкодом.

- **AC-3:** Given у меня настроен scene change detection (опционально, по настройке), When содержимое экрана меняется >30% (по сравнению с предыдущим скриншотом), Then делается внеплановый скриншот.

- **AC-4:** Given захват идёт, When встреча завершилась, Then я вижу все скриншоты в протоколе, упорядоченные по таймкоду, с возможностью просмотра и удаления лишних.

- **AC-5:** Given интервал 30 сек × 2 ч = 240 скриншотов, When встреча завершается, Then скриншоты занимают ≤500 МБ на диске (PNG 1920×1080 ≈ 2 МБ → после конвертации в JPEG q=85 ≈ 500 КБ → 120 МБ итого).

- **AC-6:** Given я хочу остановить capture, When я нажимаю «⏹ Остановить capture», Then захват прекращается, ресурсы освобождаются.

- **AC-7:** Given встречу веду я, а не демонстрант, When я пытаюсь включить capture, Then появляется tooltip «Для скриншотов нужно быть демонстрантом экрана в Телемост. Попросите участника включить демонстрацию или используйте US-047 (ручной capture)».

- **AC-8:** Given скриншоты сделаны, When я экспортирую DOCX (US-024), Then они автоматически встраиваются в протокол с привязкой к репликам.

## Технические заметки
- Frontend: `navigator.mediaDevices.getDisplayMedia({video: true, audio: false})` → `<video>` → `<canvas>` → `toDataURL('image/png')` → Blob → upload.
- Backend: принимает multipart, сохраняет в файловую систему, регистрирует в `screenshots` таблице.
- Scene change detection: pixel diff через `<canvas>` сравнение или perceptual hash (pHash).
- Compression: PIL `Image.save(format='JPEG', quality=85)` для больших скриншотов.
- Лимит: ≤500 скриншотов на протокол (защита от переполнения диска).
- Privacy: capture только когда пользователь явно запустил — никаких скрытых захватов.
