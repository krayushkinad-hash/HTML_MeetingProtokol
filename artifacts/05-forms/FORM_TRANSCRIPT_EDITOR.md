# FORM_TRANSCRIPT_EDITOR: Форма редактирования текста реплики

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-8 |
| **Название формы** | Редактор реплики (in-place) |
| **Путь доступа** | ProtocolView → клик по тексту реплики (двойной клик) |
| **Цель и назначение** | Редактирование распознанного текста реплики с историей изменений (undo) |
| **Этап бизнес-процесса** | P-01 «Подготовка протокола» — шаг 4 (коррекция) |
| **Входные данные** | `utterance.text`, `utterance.id` |
| **Выходные данные** | Обновлённый `utterance.text`, новая запись в `protocol_version` (для undo) |

## 2. Структура и навигация

- **Шапка:** отсутствует (форма in-place).
- **Тело:** поле textarea с текущим текстом реплики, метаданные (таймкод, оратор, confidence), кнопки.
- **Подвал:** кнопки «Сохранить» (Ctrl+Enter), «Отмена» (Escape), «История».
- **Адаптивность:** форма занимает всю ширину контейнера реплики.
- **Табы:** отсутствуют.

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Двойной клик по реплике | Текст заменяется на textarea, фокус в поле |
| Ввод текста | Под полем показывается счётчик символов, кнопка «Сохранить» активна |
| `Ctrl+Enter` | Сохранение изменений |
| `Escape` | Отмена редактирования, возврат к исходному тексту |
| `Ctrl+Z` (в textarea) | Отмена ввода (нативный undo браузера) |
| Нажата «Сохранить» | PATCH /api/v1/utterances/{id}/text, обновление UI, toast «Изменено» |
| Нажата «История» | Открывается модалка 3.2.1 со списком версий |
| Изменения не сохранены + клик вне формы | Подтверждение «Сохранить изменения?» |
| Confidence < 0.7 (низкая) | Жёлтая подсветка поля, иконка `[?]` слева |
| Confidence < 0.4 (очень низкая) | Красная подсветка, предупреждение «Требует проверки» |

## 5. Ошибки и информационные сообщения

| Тип | Условие | Вид | Текст |
|---|---|---|---|
| Ошибка | Пустой текст | Под полем | «Текст не может быть пустым» |
| Ошибка | >2000 символов | Под полем | «Текст слишком длинный (макс. 2000 символов)» |
| Ошибка | Сеть недоступна | Баннер | «Не удалось сохранить изменение. Попробуйте снова» |
| Ошибка | Версия устарела (conflict) | Модалка | «Реплика была изменена в другом месте. Обновить?» |
| Предупреждение | Закрытие без сохранения | Модалка | «Сохранить изменения?» (Да/Нет/Отмена) |
| Предупреждение | Низкая confidence | Иконка | «[?] Низкая уверенность распознавания (0.XX)» |
| Информация | Сохранение | Зелёный тост | «Изменено в 14:32:05» |
| Информация | Восстановление версии | Тост | «Восстановлена версия #N» |

## 6. Сценарии по умолчанию (Состояния)

- **Просмотр:** текст реплики, hover показывает иконку «редактировать».
- **Редактирование:** textarea с фокусом, кнопки активны.
- **Низкая confidence:** жёлтая подсветка, иконка `[?]`.
- **Очень низкая confidence:** красная подсветка.
- **Сохранение:** кнопка «Сохранить» → спиннер, остальные неактивны.
- **История:** модалка с версиями, текущая выделена жирным.
- **Conflict:** модалка с предложением обновить/перезаписать.
- **Только чтение (P-02 офлайн):** textarea неактивна, tooltip «Изменения доступны только в Windows».

## 7. Требования к данным (Маппинг)

### Источник данных

| Поле формы | Источник | Описание |
|---|---|---|
| Исходный текст | `utterance.text` | Текущий распознанный текст |
| Confidence | `utterance.confidence` | Уверенность модели (0.000-1.000) |
| Таймкод | `utterance.start_sec` / `end_sec` | Форматируется в HH:MM:SS |
| Оратор | `speaker.display_name` | Имя или метка SPEAKER_XX |

### Пример JSON для отправки

```json
PATCH /api/v1/utterances/{id}/text
{
  "text": "По бюджету на четвёртый квартал осталось 1.2 миллиона",
  "version_snapshot": true
}

→ 200 OK
{
  "id": "uuid",
  "text": "По бюджету на четвёртый квартал осталось 1.2 миллиона",
  "text_original": "По бюджету на четвертый квартал осталось 1.2 миллиона",  // предыдущее значение
  "updated_at": "2026-09-14T20:32:05Z",
  "version_number": 5
}
```

### Эндпоинт

- `PATCH /api/v1/utterances/{id}/text` — обновить текст реплики
- `GET /api/v1/utterances/{id}/versions` — история изменений
- `POST /api/v1/utterances/{id}/restore/{version}` — восстановить версию

### Связанные таблицы БД

- `utterance` (text, text_original, updated_at)
- `protocol_version` (snapshot JSON, version_number, changed_by='user', change_reason)

| Accessibility | WCAG 2.1 AA, ARIA-live для toast-сообщений |
| Горячие клавиши | Ctrl+Enter, Escape, Ctrl+Z |
| Локализация | ru-RU |

## 9. Технические требования

- Frontend: Vanilla JS, contenteditable или `<textarea>`.
- Backend: FastAPI + Pydantic для валидации.
- ORM: SQLAlchemy, транзакция обновляет `utterance` + создаёт запись в `protocol_version`.
- Хранение черновика: localStorage ключ `html_mp_draft_{protocol_id}_{utterance_id}`.
- Conflict resolution: optimistic locking через `If-Match` header или version number.

## 10. Примечания

- Связь с US-048: «Как Алексей, я хочу отредактировать текст реплики в удобном интерфейсе с историей изменений (undo)».
- Поле `text_original` сохраняет предыдущее значение для восстановления.
- При редактировании текста поле `confidence` НЕ меняется (остаётся как было при распознавании).
- В будущем: bulk-редактирование нескольких реплик сразу.
