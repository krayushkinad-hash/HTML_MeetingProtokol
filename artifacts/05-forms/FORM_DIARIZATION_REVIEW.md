# FORM_DIARIZATION_REVIEW: Форма коррекции диаризации

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-9 |
| **Название формы** | Просмотр и коррекция результатов диаризации |
| **Путь доступа** | ProtocolView → вкладка «Ораторы» / `dist/index.html` → Протокол → Ораторы |
| **Цель и назначение** | Просмотр автодиаризации, ручная корректировка меток ораторов, объединение/разделение ораторов |
| **Этап бизнес-процесса** | P-01 «Подготовка протокола» — шаг 3 (диаризация + коррекция) |
| **Входные данные** | `speaker.*`, `utterance.speaker_id`, `diarization_result.*` |
| **Выходные данные** | Обновлённые `speaker.display_name`, `utterance.speaker_id`, пересчёт `diarization_result.der_score` |

## 2. Структура и навигация

- **Шапка:** заголовок «Ораторы протокола», DER-метрика, кнопки «Сохранить» и «Отмена».
- **Левая панель:** список ораторов (SPEAKER_00, SPEAKER_01...) с цветными маркерами, количество реплик, имя.
- **Правая панель:** реплики выбранного оратора с возможностью переназначения (drag-and-drop или select).
- **Подвал:** кнопки «Сохранить», «Отмена».
- **Адаптивность:** на узких экранах (<1024px) панели перестраиваются в табы.
- **Табы:** отсутствуют (двухпанельный layout).

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Открытие формы | Загружаются все ораторы + их реплики, выбран первый оратор |
| Клик на оратора в левой панели | Правая панель показывает реплики этого оратора |
| Изменение имени (3.1.1) | Inline-редактирование, автосохранение через 1 сек |
| Изменение цвета (3.1.2) | Маркер реплик в правой панели меняет цвет |
| Чекбокс «Это пользователь» (3.1.3) | Сохранение, фильтрация в UI |
| Клик «Перенести» на реплике | Реплика убирается из текущего списка, добавляется к выбранному оратору |
| Drag-and-drop реплики на оратора | Аналогично кнопке «Перенести» |
| Клик «Объединить» | Открывается модалка 3.3.1-3.3.3 |
| Клик «Удалить оратора» | Подтверждение, удаление только если нет реплик |
| Нажата «Сохранить» | PATCH /api/v1/speakers/* (батч), toast «Изменения сохранены» |

## 5. Ошибки и информационные сообщения

| Тип | Условие | Вид | Текст |

| Предупреждение | Не сохранены изменения | Модалка | «Сохранить изменения перед закрытием?» |
| Предупреждение | Удаление оратора | Модалка | «Удалить оратора "<X>"? Действие нельзя отменить» |
| Информация | Сохранение | Зелёный тост | «Изменения сохранены (N правок)» |
| Информация | DER метрика | Метка | «DER: 18.5% (норма ≤20%)» |

## 6. Сценарии по умолчанию (Состояния)

- **Просмотр:** все ораторы с метками SPEAKER_XX, реплики в правой панели.
- **Коррекция:** активное поле имени, реплики можно перетаскивать.
- **Объединение:** модалка с выбором источника/цели.
- **Удаление:** модалка подтверждения.
- **Сохранение:** спиннер, остальные элементы неактивны.
- **Конфликт версий:** модалка «Данные были изменены».
- **Офлайн (P-02):** форма только для просмотра, кнопки редактирования скрыты.

## 7. Требования к данным (Маппинг)

### Источник данных

| Поле формы | Источник | Описание |
|---|---|---|
| Список ораторов | `GET /api/v1/protocols/{id}/speakers` | Все ораторы протокола |
| Реплики оратора | `GET /api/v1/speakers/{id}/utterances` | Реплики конкретного оратора |
| DER метрика | `diarization_result.der_score` | Качество диаризации |

### Пример JSON

```json
GET /api/v1/protocols/{id}/speakers → 200 OK
[
  {
    "id": "uuid",
    "speaker_label": "SPEAKER_00",
    "display_name": "Алексей Краюшкин",
    "color": "#FF6B35",
    "is_user": true,
    "utterance_count": 42
  },
  ...
]

PATCH /api/v1/speakers/{id}
{
  "display_name": "Алексей",
  "color": "#FF6B35",
  "is_user": true
}

POST /api/v1/speakers/merge
{
  "source_id": "uuid_source",
  "target_id": "uuid_target",
  "new_display_name": "Алексей"
}
```

### Эндпоинты

- `GET /api/v1/protocols/{id}/speakers` — список ораторов
- `GET /api/v1/speakers/{id}/utterances` — реплики оратора
- `PATCH /api/v1/speakers/{id}` — обновить оратора
- `POST /api/v1/speakers/merge` — объединить ораторов
- `DELETE /api/v1/speakers/{id}` — удалить оратора
- `PATCH /api/v1/utterances/{id}/speaker` — переназначить реплику

### Связанные таблицы БД

- `speaker` (display_name, color, is_user, voice_profile_id)
- `utterance` (speaker_id) — обновляется при переназначении
- `diarization_result` (der_score, num_speakers_detected, num_speakers_expected)

## 8. Нефункциональные требования

| Метрика | Требование |
|---|---|
| Время загрузки ораторов | p95 < 200 мс |
| Время переназначения реплики | p95 < 150 мс |
| Drag-and-drop latency | < 50 мс |
| Размер компонента | < 80 КБ (с drag-and-drop) |
| Accessibility | WCAG 2.1 AA, ARIA для drag-and-drop (альтернатива — кнопки) |
| Горячие клавиши | Ctrl+S (сохранить), Ctrl+Z (undo переназначения) |
| Локализация | ru-RU |

## 9. Технические требования

- Frontend: Vanilla JS или библиотека drag-and-drop (SortableJS).
- Backend: FastAPI с batch endpoints для оптимизации.
- ORM: SQLAlchemy, каскадное обновление `utterance.speaker_id`.
- Кэш: ораторы в IndexedDB для офлайна (только просмотр).

## 10. Примечания

- Связь с US-007 (диаризация), US-008 (ручная корректировка).
- При объединении ораторов все реплики переназначаются атомарно (в транзакции).
- В будущем: автоматическое предложение имён через LLM (например, "по контексту похоже на Петрова").
