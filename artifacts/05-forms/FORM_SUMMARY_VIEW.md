# FORM_SUMMARY_VIEW: Просмотр саммари встречи

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-11 |
| **Название формы** | Саммари протокола (AI-сгенерированное) |
| **Путь доступа** | ProtocolView → вкладка «Саммари» / `dist/index.html` → Протокол → Саммари |
| **Цель и назначение** | Просмотр и регенерация саммари встречи через LLM (Hermes / GigaChat / Ollama) |
| **Этап бизнес-процесса** | P-01 «Подготовка протокола» — шаг 6 (AI-фичи) |
| **Входные данные** | `summary.*`, протокол, реплики |
| **Выходные данные** | Обновлённый/созданный `summary` |

## 2. Структура и навигация

- **Шапка:** заголовок «Саммари встречи», провайдер LLM, кнопка «Регенерировать».
- **Тело:** текст саммари в форматированном виде (Markdown), метаданные.
- **Подвал:** кнопки «Копировать», «Вставить в DOCX», «Скачать .md».
- **Адаптивность:** на узких экранах одна колонка, кнопки в шапке.
- **Табы:** 3 таба — «Саммари» (default), «Ключевые темы», «Решения».

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Открытие формы | Загрузка существующего summary, если есть; иначе — кнопка «Сгенерировать» |
| Клик «Сгенерировать» (если summary нет) | POST /api/v1/ai/summarize, спиннер, через ~5-10 сек появляется текст |
| Клик «Регенерировать» | Модалка 3.4.1-3.4.5, при подтверждении POST /api/v1/ai/summarize |
| Клик «Копировать» | Текст саммари копируется в буфер обмена, toast «Скопировано» |
| Клик «Вставить в DOCX» | Текст добавляется в шаблон DOCX-экспорта |
| Клик «Скачать .md» | Скачивается файл `summary_{protocol_id}.md` |
| Переключение табов | Показ соответствующего контента |
| Ошибка провайдера | Автопереключение на следующий (hermes → gigachat → local_ollama) |
| Streaming ответа | Постепенное появление текста (если поддерживается API) |

| Информация | Переключение провайдера | Тост | «Переключение на <X>...» |

## 6. Сценарии по умолчанию (Состояния)

- **Саммари нет:** кнопка «Сгенерировать», placeholder «Саммари ещё не создано».
- **Саммари есть:** текст, кнопки «Регенерировать», «Копировать», «Скачать».
- **Генерация:** спиннер, прогресс-бар (если есть streaming), остальные элементы неактивны.
- **Ошибка:** баннер сверху, кнопка «Повторить».
- **Пустые ключевые темы:** «Нет данных. Регенерируйте саммари».
- **Офлайн (P-02):** саммари доступно только для просмотра, кнопки генерации скрыты.

## 7. Требования к данным (Маппинг)

### Источник данных

| Поле формы | Источник | Описание |
|---|---|---|
| Текст саммари | `GET /api/v1/protocols/{id}/summary` | Существующее саммари |
| Провайдер | `user_setting.llm_provider` | По умолчанию |
| Текст протокола | `utterance.text` (все реплики) | Входные данные для AI |

### Пример JSON

```json
GET /api/v1/protocols/{id}/summary → 200 OK
{
  "id": "uuid",
  "protocol_id": "uuid",
  "text": "## Краткое резюме\n\nНа встрече обсудили бюджет Q4...",
  "provider": "hermes",
  "model": "hermes-3-70b",
  "tokens_used": 4521,
  "regenerated": 2,
  "generated_at": "2026-09-14T20:00:00Z"
}

POST /api/v1/ai/summarize
{
  "protocol_id": "uuid",
  "provider": "hermes",
  "style": "structured",
  "max_words": 500,
  "include_citations": true,
  "additional_instructions": "Акцент на бюджете"
}
```

### Эндпоинты

- `GET /api/v1/protocols/{id}/summary` — получить саммари
- `POST /api/v1/ai/summarize` — сгенерировать саммари
- `POST /api/v1/ai/summarize/stream` — streaming версия

### Связанные таблицы БД

- `summary` (id, protocol_id UNIQUE, text, provider, model, generated_at, tokens_used, regenerated)
- `user_setting` (llm_provider, llm_model)

## 8. Нефункциональные требования

| Метрика | Требование |
|---|---|
| Время генерации саммари (1 час протокола) | p95 < 10 сек |
| Время загрузки существующего саммари | p95 < 200 мс |
| Размер компонента | < 80 КБ (с Markdown renderer) |
| Markdown renderer | marked.js или markdown-it |
| Streaming TTFB | < 2 сек |
| Accessibility | WCAG 2.1 AA, ARIA-live для стриминга |
| Локализация | ru-RU |

## 9. Технические требования

- Frontend: Vanilla JS + markdown-it для рендеринга.
- Backend: FastAPI с поддержкой streaming через Server-Sent Events.
- AI: Hermes API (приоритет), GigaChat API (альтернатива), Ollama (локально).
- Промпт: системный промпт для саммари + пользовательские инструкции.
- Кэш: саммари хранится в БД, не пересчитывается при повторных открытиях.

## 10. Примечания

- Связь с US-022 (саммари), US-037 (Telegram-бот `/summarize`).
- При регенерации предыдущее саммари сохраняется в `summary.regenerated` (счётчик).
- При экспорте в DOCX саммари добавляется как отдельная секция.
- В будущем: разделение саммари по ораторам («что сказал Петров»).
