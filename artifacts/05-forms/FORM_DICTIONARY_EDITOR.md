# FORM_DICTIONARY_EDITOR: Форма редактирования словаря терминов

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-7 |
| **Название формы** | Редактор словаря пользовательских терминов |
| **Путь доступа** | Настройки → Словарь терминов / `dist/index.html` → Настройки → Словарь |
| **Цель и назначение** | Создание и редактирование пользовательского словаря терминов (фамилии, названия, аббревиатуры) для передачи в Whisper prompt |
| **Этап бизнес-процесса** | P-01 «Подготовка протокола» — шаг 1.5 (преднастройка словаря) |
| **Входные данные** | Существующий словарь из `dictionary` (БД), текущий набор терминов |
| **Выходные данные** | Обновлённый `dictionary` (≤1000 записей), whisper_prompt |

## 2. Структура и навигация

- **Шапка:** заголовок «Словарь терминов», кнопки «Назад» и «Сохранить».
- **Тело:** поле поиска, таблица терминов с колонками (термин, категория, вес, действия), кнопка «Добавить термин».
- **Подвал:** кнопки «Сохранить» и «Отмена».
- **Адаптивность:** на узких экранах (<768px) таблица перестраивается в карточки.
- **Табы:** отсутствуют (одна страница).

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Открытие формы | Загружаются все термины из `dictionary`, отображаются в таблице |
| Поиск (ввод в 3.1.1) | Фильтрация таблицы по подстроке (регистронезависимо), debounce 300 мс |
| Нажата «Добавить термин» | Открывается модалка 3.3.1-3.3.4 с пустыми полями |
| Клик «редактировать» в строке | Модалка открывается с предзаполненными полями |
| Клик «удалить» в строке | Подтверждение «Удалить термин "<термин>"?» |
| Сохранение модалки | POST /api/v1/dictionary, обновление таблицы без перезагрузки |
| Нажата «Сохранить» в шапке | PATCH /api/v1/user-setting/whisper-prompt (собирается из всех терминов), редирект |
| Валидация модалки | Подсветка невалидных полей, фокус на первое невалидное |
| Словарь пуст | Сообщение «Словарь пуст. Добавьте термины для улучшения распознавания» |

## 5. Ошибки и информационные сообщения

| Тип | Условие | Вид | Текст |
|---|---|---|---|
| Ошибка | Термин уже существует | Баннер | «Термин "<X>" уже есть в словаре» |
| Ошибка | Вес вне диапазона | Под полем | «Вес должен быть от 0.00 до 1.00» |
| Ошибка | Превышен лимит (1000) | Модалка | «Достигнут лимит словаря (1000 терминов). Удалите неиспользуемые» |
| Ошибка | Сеть недоступна | Баннер | «Не удалось сохранить словарь. Проверьте подключение» |
| Предупреждение | Удаление термина | Модалка | «Удалить термин "<X>"? Действие нельзя отменить» |
| Информация | Сохранение | Зелёный тост | «Словарь сохранён (N терминов)» |

## 6. Сценарии по умолчанию (Состояния)

- **Новая запись:** словарь пуст, показано сообщение «Словарь пуст».
- **Словарь заполнен:** таблица с терминами, сортировка по категории/имени.
- **Поиск активен:** таблица отфильтрована, счётчик «Найдено: N».
- **Редактирование:** модалка открыта, фон затемнён.
- **Удаление:** модалка подтверждения.
- **Загрузка:** спиннер в таблице, остальные элементы неактивны.
- **Сохранение:** кнопка «Сохранить» показывает прогресс-бар, остальные неактивны.
- **Ошибка сети:** баннер сверху, форма остаётся работоспособной, можно повторить сохранение.

## 7. Требования к данным (Маппинг)

### Источник данных

| Поле формы | Источник | Описание |
|---|---|---|
| Таблица терминов | `GET /api/v1/dictionary` | Список всех терминов пользователя |
| Категория | ENUM `term_category` | name / product / abbreviation / other |

### Пример JSON для отправки

```json
POST /api/v1/dictionary
{
  "term": "Краюшкин",
  "category": "name",
  "weight": 1.00
}

GET /api/v1/dictionary → 200 OK
[
  {
    "id": "uuid",
    "term": "Краюшкин",
    "category": "name",
    "weight": 1.00,
    "created_at": "2026-09-14T20:00:00Z"
  },
  ...
]
```

### Эндпоинт

- `GET /api/v1/dictionary` — получить все термины
- `POST /api/v1/dictionary` — добавить термин
- `PATCH /api/v1/dictionary/{id}` — обновить термин
- `DELETE /api/v1/dictionary/{id}` — удалить термин

### Связанные таблицы БД

- `dictionary` (id, user_setting_id, term, category, weight, created_at)
- Индекс `idx_dictionary_user_term` UNIQUE на `(user_setting_id, LOWER(term))`

## 8. Нефункциональные требования

| Метрика | Требование |
|---|---|
| Время загрузки словаря (1000 терминов) | p95 < 200 мс |
| Время поиска (с debounce 300 мс) | p95 < 100 мс |
| Размер формы (HTML+JS+CSS) | < 50 КБ |
| Accessibility | WCAG 2.1 AA: tab navigation, ARIA, focus indicators |
| Горячие клавиши | `Ctrl+N` — новый термин, `Ctrl+S` — сохранить, `Escape` — закрыть модалку |
| Кроссбраузерность | Chrome/Edge/Firefox/Safari (последние 2 версии) |
| Локализация | ru-RU |

## 9. Технические требования

- Frontend: Vanilla JS (без фреймворков), компонент `<DictionaryEditor>`.
- Backend: FastAPI endpoint `/api/v1/dictionary/*`.
- ORM: SQLAlchemy модель `Dictionary`.
- Хранение: PostgreSQL + синхронизация в IndexedDB для офлайна.
- Кэш: термины в памяти фронта после первой загрузки.
- Валидация: zod / ajv на клиенте, pydantic на сервере.

## 10. Примечания

- Связь с US-047: «Как Алексей, я хочу создать словарь пользовательских терминов и передавать его в Whisper как prompt».
- Словарь собирается в строку `whisper_prompt = "Краюшкин, GigaChat, FastAPI, ..."` (через запятую) и передаётся в Whisper при запуске транскрипции.
- Категория «name» имеет наивысший приоритет в prompt (первые в списке).
- В будущем: импорт терминов из CSV / Excel.
