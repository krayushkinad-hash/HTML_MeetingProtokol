# FORM_UPLOAD: Форма загрузки аудио/видеофайла

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-1 |
| **Название формы** | Загрузка аудио/видеофайла |
| **Путь доступа** | Главная страница → кнопка «Загрузить файл» / `dist/index.html` → пун меню «Загрузить» |
| **Цель и назначение** | Загрузить локальный аудио/видеофайл или скачать по HTTPS-ссылке для последующей транскрипции |
| **Этап бизнес-процесса** | P-01 «Подготовка протокола встречи» — шаг 1 (загрузка файла) |
| **Входные данные** | Локальный файл (mp3/wav/mp4/mkv) или HTTPS-ссылка (Яндекс.Диск/Google Drive/Mail.ru) |
| **Выходные данные** | Созданный протокол со статусом «Загружен», файл на диске `~/.html_mp/protocols/<id>/source.<ext>` |

## 2. Структура и навигация

- **Шапка:** заголовок «Загрузка файла», кнопка «Назад» (закрывает форму).
- **Тело:** две вкладки-переключателя: «Локальный файл» и «По ссылке». Ниже — поле ввода (file или text), кнопка «Загрузить», прогресс-бар.
- **Подвал:** кнопки «Загрузить» и «Отмена».
- **Адаптивность:** на узких экранах (<600 px) вкладки перестраиваются в выпадающий список.
- **Табы:** две вкладки, активная по умолчанию — «Локальный файл».

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Открытие формы | Поля пусты, активна вкладка «Локальный файл» |
| Выбран файл | Под полем показывается имя, размер, тип; если >2 ГБ — предупреждение |
| Нажата «Загрузить» (локальный) | Файл потоково сохраняется на диск (chunk ≤8 МБ); показывается прогресс-бар; после завершения — переход на ProtocolView со статусом «Загружен» |
| Нажата «Загрузить» (по ссылке) | Backend скачивает файл по HTTPS; показывается прогресс-бар; при ошибке — сообщение и форма остаётся открытой |
| Скачивание прервалось | Автоматическое возобновление через HTTP Range или сообщение «Начать заново» |
| Невалидный формат | Сообщение об ошибке, фокус на поле выбора файла |
| Самоподписанный HTTPS | Экран подтверждения «Сертификат невалиден. Продолжить?» |
| Нажата «Отмена» | Закрытие формы, возврат на главную страницу без сохранения |
| RSS >80% RAM | Прогресс-бар показывает предупреждение «Приближаемся к лимиту памяти» |

## 6. Сценарии по умолчанию (Состояния)

- **Новая запись:** поля пусты, активна вкладка «Локальный файл», кнопка «Загрузить» неактивна до выбора файла.
- **Файл выбран:** показано имя/размер/тип, кнопка «Загрузить» активна.
- **Загрузка:** прогресс-бар от 0 до 100%, кнопки неактивны.
- **Успех:** зелёный тост 3 сек, редирект на ProtocolView.
- **Ошибка:** красный баннер сверху, форма остаётся открытой.
- **Файл большой:** жёлтый баннер с кнопками «Да, продолжить» / «Отмена».
- **Офлайн (P-02):** вкладка «По ссылке» неактивна с tooltipом «Требуется интернет», доступна только загрузка локального файла.

## 7. Требования к данным (Маппинг)

- **Источник данных:** нет (форма только собирает данные).
- **Пример JSON для отправки:**

```json
{
  "source": "local",
  "filename": "meeting_2026-09-14.mp4",
  "size_bytes": 157286400,
  "mime_type": "video/mp4",
  "extension": "mp4"
}
```

Для ссылки:
```json
{
  "source": "url",
  "url": "https://drive.google.com/file/d/abc123/view",
  "checksum": null
}
```

- **Эндпоинт:** `POST /api/v1/transcribe/upload` (multipart/form-data) или `POST /api/v1/transcribe/from-url` (application/json).
- **Ответ:**

```json
{
  "protocol_id": "abc-123-def",
  "status": "loaded",
  "file_path": "/home/user/.html_mp/protocols/abc-123-def/source.mp4",
  "size_bytes": 157286400
}
```

- **Формат хранения:** файлы на диске в `~/.html_mp/protocols/<protocol_id>/`, метаданные в IndexedDB.

## 8. Нефункциональные требования

- **Производительность:** загрузка 100 МБ файла за ≤30 сек на SSD; прогресс-бар обновляется каждые 200 мс.
- **Защита:** валидация типа и размера на клиенте и на сервере (защита от подделки); HTTPS-only для ссылок (кроме localhost); предупреждение для самоподписанных сертификатов.
- **Горячие клавиши:** Ctrl+O — открыть диалог выбора файла; Esc — закрыть форму; Enter — загрузить (если файл выбран).
- **Кроссбраузерность:** Chromium 100+, Firefox 100+, Safari 14+; поддержка Drag & Drop для файлов.
- **Масштабируемость:** форма должна работать с файлами до 10 ГБ без OOM (chunk ≤8 МБ).
- **Доступность (WCAG 2.1 AA):** все поля имеют `<label>`; ошибки связаны через `aria-describedby`; фокус видимый; навигация с клавиатуры.

## 9. Технические требования

- **Библиотеки:** стандартный HTML5 File API, IndexedDB, нативный `<input type="file">`.
- **Backend:** FastAPI с `UploadFile` для multipart; `httpx` для скачивания по ссылке.
- **Форматы:** mp3, wav (аудио), mp4, mkv (видео); ffmpeg для декодирования аудио из видео.
- **Особые требования:** потоковое чтение файла (chunk ≤8 МБ), сохранение сразу на диск (не в RAM), мониторинг RSS процесса.

## 10. Примечания

- Форма реализована как модульный компонент в `src/js/views/upload.js` (планируется добавить).
- В MVP поддерживается только HTTPS-валидация для ссылок; HTTP и FTP не поддерживаются.
- Drag & Drop файлов на зону формы — расширение (не в MVP).
- Несколько файлов за раз — не поддерживается (по одному протоколу = один файл).
