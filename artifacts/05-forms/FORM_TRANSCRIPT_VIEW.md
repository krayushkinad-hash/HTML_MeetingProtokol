# FORM_TRANSCRIPT_VIEW: Просмотр транскрипции с таймкодами

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-4 |
| **Название формы** | Просмотр транскрипции с навигацией по видео |
| **Путь доступа** | Из FORM_PROTOCOL_VIEW (правая колонка) или ссылка `#transcript` |
| **Цель и назначение** | Просмотр списка реплик с таймкодами, поиск, клик → переход к видео |
| **Этап бизнес-процесса** | P-01 «Просмотр результата» / P-03 «Подготовка в командировке» |
| **Входные данные** | Массив реплик (utterances[]), список ораторов (speakers{}) |
| **Выходные данные** | Отрендеренный список реплик с подсветкой активной, фильтрами |

## 2. Структура и навигация

- **Шапка:** поле поиска, фильтр по оратору, сортировка (по времени / по оратору).
- **Тело:** прокручиваемый список реплик. Каждая реплика — карточка:
  - Метаданные: имя оратора + цветовая полоса слева, таймкод HH:MM:SS
  - Текст реплики
  - Кнопки: ⭐ (пометить важное), 📌 (создать action item), 🔗 (скопировать ссылку на момент)
- **Подвал:** счётчик реплик, кнопка «Прокрутить к активной».
- **Адаптивность:** на узких экранах карточки на всю ширину; кнопки перестраиваются в меню «⋯».

## 3. Спецификация полей ввода

| № | Подпись | Тип | Обяз. | Default | Значения | Валидация |
|---|---|---|---|---|---|---|
| 3.1 | Поиск | text (search) | Нет | "" | — | Длина ≥2 символов для фильтрации |
| 3.2 | Фильтр по оратору | select | Нет | "Все" | Список ораторов + "Все" | — |
| 3.3 | Сортировка | select | Нет | "По времени" | "По времени", "По оратору" | — |
| 3.4 | Только помеченные | checkbox | Нет | false | true/false | — |

### Отображаемые данные (только чтение)

| № | Поле | Тип | Источник |
|---|---|---|---|
| 3.10 | Имя оратора | text | `speakers[speaker_id]` |
| 3.11 | Таймкод | text | `utterance.start` → HH:MM:SS |
| 3.12 | Текст | text | `utterance.text` |
| 3.13 | Длительность | text | `utterance.end - utterance.start` |
| 3.14 | Пометка «важное» | icon | `utterance.important` |
| 3.15 | Привязка к action item | icon | `utterance.action_item_id` |

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Клик по карточке реплики | Видеоплеер перематывается на таймкод; карточка подсвечивается синей рамкой; автопрокрутка к активной |
| Клик по таймкоду | То же, что клик по карточке + копирование ссылки в буфер: `html-mp://<protocol_id>?t=<sec>` |
| Клик ⭐ | Пометка реплики как важной; в итоговом DOCX — выделение |
| Клик 📌 | Открытие мини-формы «Создать action item» (кто / что / когда) |
| Ввод в поиск | Через 300 мс фильтрация; подсветка совпадений жёлтым; счётчик «найдено N из M» |
| Выбор оратора | Фильтрация списка; счётчик «N реплик оратора X» |
| Переключение сортировки | Перерисовка списка (с анимацией) |
| Чекбокс «Только помеченные» | Показ только ⭐-реплик |
| Hover на реплику | Показ мини-кнопок ⭐ 📌 🔗 |
| Офлайн (P-02) | Все данные из IndexedDB; функционально идентично |

## 5. Ошибки и информационные сообщения

| Тип | Условие | Текст |
|---|---|---|
| Ошибка | Нет данных | «Транскрипция отсутствует. Возможно, обработка ещё идёт.» |
| Предупреждение | Поиск без результатов | «Ничего не найдено по запросу «<текст>». Попробуйте другое слово или снимите фильтры.» |
| Информация | Скопирована ссылка | «Ссылка на момент скопирована в буфер обмена» |
| Информация | Реплика помечена | «Реплика помечена как важная. Будет выделена в итоговом DOCX.» |
| Информация | | «Action item создан и привязан к реплике.» |

## 6. Сценарии по умолчанию (Состояния)

- **Пусто:** «Транскрипция отсутствует».
- **Готов:** все реплики видны, активная — с синей рамкой.
- **Поиск:** подсвечены совпадения, остальные скрыты или полупрозрачны.
- **Фильтр по оратору:** только реплики одного оратора.
- **Сортировка по оратору:** реплики сгруппированы по ораторам.
- **Только помеченные:** видны только ⭐-реплики.
- **Создание action item:** мини-форма открыта, остальные реплики затемнены.

## 7. Требования к данным (Маппинг)

- **Источник:** IndexedDB `utterances` + `speakers` для протокола.
- **Пример IndexedDB-объекта:**

```json
{
  "id": "utt-001",
  "protocol_id": "abc-123-def",
  "start": 32.5,
  "end": 48.2,
  "speaker_id": "SPEAKER_00",
  "text": "По бюджету на четвёртый квартал — у нас осталось 1.2 миллиона.",
  "important": true,
  "action_item_id": null
}
```

- **Эндпоинты:** `PATCH /api/v1/utterances/<id>/important` (пометка), `PATCH /api/v1/utterances/<id>/speaker` (смена оратора), `POST /api/v1/action-items` (создание action item).
- **Локальное хранилище:** IndexedDB store `utterances`, индексы по `protocol_id`, `speaker_id`, `important`.

## 8. Нефункциональные требования

- **Производительность:** рендер 1000 реплик — ≤300 мс; виртуализация для >500; поиск — ≤300 мс debounce.
- **Защита:** доступ только по локальному backend; данные не уходят.
- **Горячие клавиши:** Ctrl+F — фокус на поиск; ↑/↓ — навигация по репликам; Enter — открыть активную в видео; Shift+Enter — пометить важное.
- **Кроссбраузерность:** Chromium 100+, Firefox 100+, Safari 14+.
- **Масштабируемость:** виртуализация списка (рендер видимых + буфер 20).
- **Доступность:** каждая реплика имеет `aria-label`; активная реплика объявляется; пометки ⭐ — `aria-pressed`.

## 9. Технические требования

- **Frontend:** нативный JS с виртуализацией (свой `VirtualList` или `IntersectionObserver`).
- **Хранение:** IndexedDB с индексами по `protocol_id`, `speaker_id`.
- **Backend:** FastAPI для синхронизации изменений (если есть).
- **Особые требования:** lazy-load реплик порциями по 100 штук для длинных встреч.

## 10. Примечания

- Цвет оратора вычисляется из `speaker_id` через HSL (фиксированная S=70%, L=50%).
- При большом количестве ораторов (>10) цвета могут повторяться — приоритет у тех, кто говорит больше.
- Возможность экспорта отдельной реплики (одна реплика → DOCX) — расширение (v2).
