# FORM_BOT_SETTINGS: Настройки Telegram-бота (AI-прокси)

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-12 |
| **Название формы** | Настройки Telegram-бота |
| **Путь доступа** | Настройки → Telegram-бот / `dist/index.html` → Настройки → Telegram |
| **Цель и назначение** | Управление Telegram-ботом: провайдер LLM (Hermes / GigaChat), whitelist пользователей, уведомления |
| **Этап бизнес-процесса** | P-01 «Подготовка протокола» — преcетup (конфигурация) |
| **Входные данные** | `api_user.*`, `user_setting.*` |
| **Выходные данные** | Обновлённые `api_user`, `user_setting`, регистрация webhook |

## 2. Структура и навигация

- **Шапка:** заголовок «Telegram-бот», статус подключения (онлайн/оффлайн), кнопка «Тест».
- **Тело:** секции — «Основное», «LLM-провайдеры», «Whitelist пользователей», «Уведомления», «Команды».
- **Подвал:** кнопки «Сохранить», «Отмена».
- **Адаптивность:** на узких экранах секции перестраиваются в табы.
- **Табы:** 5 табов по секциям.

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Открытие формы | Загрузка текущих настроек, проверка статуса бота (GET /health бот) |
| Клик «Тест» (3.1.5) | Отправляет тестовое сообщение админу, показывает toast «Отправлено» |
| Изменение провайдера (3.2.1) | Показ полей только для выбранного провайдера (3.2.2-3.2.6) |
| Изменение Bot Token | Кнопка «Обновить webhook» становится активной |
| Клик «+ Добавить пользователя» | Открывается модалка 3.3.1-3.3.4 |
| Клик «Тест-сообщение» на пользователе | Отправка «Бот работает!» этому пользователю |
| Клик «Сохранить» | PATCH /api/v1/bot/settings (атомарное обновление всех секций), рестарт бота при необходимости |
| Бот недоступен | Красная плашка сверху «Бот недоступен. Проверьте токен и webhook» |
| Бот активен и работает | Зелёная плашка «Бот онлайн (X пользователей)» |

## 5. Ошибки и информационные сообщения

| Тип | Условие | Вид | Текст |
|---|---|---|---|

| Ошибка | Невалидный webhook URL | Под полем | «Webhook должен начинаться с https://» |

## 6. Сценарии по умолчанию (Состояния)

- **Первый запуск:** пустые поля, красная плашка «Бот не настроен», кнопка «Сохранить» неактивна.
- **Бот настроен:** все поля заполнены, зелёная плашка «Бот онлайн».
- **Бот неактивен:** switch «Бот активен» = false, поля заблокированы.
- **Бот недоступен:** красная плашка, кнопка «Перезапустить бот».
- **Whitelist пуст:** «Нет пользователей. Добавьте хотя бы одного».
- **Сохранение:** спиннер, кнопка неактивна.

## 7. Требования к данным (Маппинг)

### Источник данных

| Поле формы | Источник | Описание |
|---|---|---|
| Текущие настройки | `GET /api/v1/bot/settings` | Все секции |
| Список пользователей | `GET /api/v1/bot/users` | Whitelist |
| Статус бота | `GET /api/v1/bot/status` | Health check |

### Эндпоинты

- `GET /api/v1/bot/settings` — получить настройки
- `PATCH /api/v1/bot/settings` — обновить
- `POST /api/v1/bot/test` — отправить тест-сообщение
- `POST /api/v1/bot/restart` — перезапустить бот
- `GET /api/v1/bot/users` — whitelist
- `POST /api/v1/bot/users` — добавить
- `PATCH /api/v1/bot/users/{id}` — обновить
- `DELETE /api/v1/bot/users/{id}` — удалить

### Связанные таблицы БД

- `api_user` (id, telegram_id UNIQUE, username, display_name, is_active, user_setting_id)
- `user_setting` (llm_provider, llm_model)

## 8. Нефункциональные требования

| Метрика | Требование |
|---|---|
| Время загрузки настроек | p95 < 200 мс |
| Время сохранения | p95 < 500 мс (включая рестарт бота) |
| Время тест-сообщения | p95 < 2 сек |
| Размер компонента | < 100 КБ (с несколькими табами) |
| Token storage | В зашифрованном виде в БД (AES-256-GCM) |
| Доступ | Только для админа (P-01) |
| Локализация | ru-RU |

## 9. Технические требования

- Frontend: Vanilla JS, компонент `<BotSettings>` с табами.
- Backend: FastAPI с защитой токенов.
- Бот: aiogram 3.x, webhook через FastAPI.
- Шифрование токенов: AES-256-GCM с мастер-ключом из переменной окружения.
- Хранение: PostgreSQL для настроек и whitelist.
- Логи: только метаданные (без токенов и PII).

## 10.Примечания

- Связь с US-041 (whitelist), US-037-038-042-043 (команды), US-039 (уведомления).
- Hermes — приоритетный провайдер, GigaChat — fallback.
- При недоступности провайдера автоматическое переключение на fallback.
- В будущем: webhook self-hosting через ngrok для разработки.
- Безопасность: токены Telegram и API-провайдеров НЕ логируются, только метаданные (длина, last 4 chars).
