# FORM_LIVE_MODE: Режим онлайн с тремя панелями

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-6 |
| **Название формы** | Режим Live Mode (видео + темы + живая транскрипция) |
| **Путь доступа** | Главная страница → переключатель «Live» в шапке; или автоматически при подключении к Яндекс Телемост |
| **Цель и назначение** | Вести протокол во время встречи, не отвлекаясь от разговора; видеть 3 панели одновременно |
| **Этап бизнес-процесса** | P-02 «Онлайн-встреча в Яндекс Телемост» |
| **Входные данные** | URL встречи в Яндекс Телемост; список ораторов (по именам); голос с микрофона |
| **Выходные данные** | Распознанные реплики с таймкодами, скриншоты экрана, помеченные важные реплики, итоговый протокол после встречи |

## 2. Структура и навигация

- **Топ-бар:** индикатор «ЗАПИСЬ ИДЁТ» (красный пульсирующий круг), URL встречи, таймер встречи, кнопки «Завершить» и «Сохранить».
- **Левая панель (40%):** iframe Яндекс Телемост (видео участников); внизу — чат Телемоста.
- **Центральная панель (20%):** список тем встречи (авто-выделяемые ключевые фразы из реплик); сверху — поиск по темам.
- **Правая панель (40%):** живая транскрипция с таймкодами; каждая реплика — карточка с оратором, таймкодом, текстом, кнопкой ⭐.
- **Адаптивность:** на узких экранах (<1200 px) панели перестраиваются в 2 колонки (видео + транскрипция), темы — в выпадающий список.

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Подключение по URL | Загрузка iframe Телемоста в левую панель; запрос разрешений на микрофон (`getUserMedia`) и (опционально) экран |
| Кто-то говорит | Через ≤3 сек реплика появляется в правой панели с подсветкой |
| Пометить ⭐ | Реплика выделяется жёлтым; в итоговом протоколе — отдельный блок «Важное» |
| Авто-выделение темы | Каждые 30 сек backend анализирует последние реплики и обновляет центральную панель |
| Клик по теме | Правая панель фильтруется по репликам, связанным с этой темой |
| Запись экрана (если включена) | Каждые 60 сек сохраняется скриншот экрана демонстранта; в IndexedDB привязывается к моменту |
| Запись системного звука | Потоковое аудио в Whisper streaming; данные не сохраняются на диск до явного «Сохранить» |
| Достижение 80% RAM | Предупреждение в топ-баре; streaming замедляется |
| Завершение встречи | Все данные сохраняются в IndexedDB; формируется протокол; открывается FORM_PROTOCOL_VIEW |
| Сохранение вручную | Принудительное сохранение в IndexedDB; реплики и скриншоты записываются на диск |
| Видео в iframe не загрузилось | Серый placeholder + кнопка «Перезагрузить iframe» |
| Браузер не поддерживает Web Audio | Баннер «Ваш браузер не поддерживает захват звука. Используйте Chrome/Edge/Firefox 100+» |
| Потеря WebSocket | Автопереподключение каждые 5 сек; индикатор «Переподключение…» |

| Тип | Условие | Текст |

## 6. Сценарии по умолчанию (Состояния)

- **До встречи:** форма пуста, поле для URL активно.
- **Подключение:** спиннер, запрос разрешений.
- **Идёт встреча:** 3 панели работают, индикатор «ЗАПИСЬ ИДЁТ», реплики появляются в реальном времени.
- **Поиск активен:** только релевантные реплики и темы.
- **Latency высокая:** реплики появляются с задержкой; индикатор latency жёлтый.
- **RAM >80%:** баннер сверху; реплики появляются медленнее.
- **Встреча завершена:** топ-бар показывает «Сохранение…», редирект на FORM_PROTOCOL_VIEW.
- **Офлайн (не применимо):** Live Mode требует сети — в офлайне недоступен.

## 7. Требования к данным (Маппинг)

- **Источники:**
  - Яндекс Телемост: iframe embed
  - Микрофон: `getUserMedia({audio: true})`
  - Экран (опционально): `getDisplayMedia({video: true, audio: false})`
  - Backend: WebSocket `/ws/transcribe/live` (стриминг аудио)
- **Пример сообщения WebSocket:**

```json
{
  "type": "utterance",
  "id": "utt-live-001",
  "start": 1547.3,
  "end": 1563.8,
  "speaker_id": "SPEAKER_00",
  "text": "Давайте обсудим бюджет на четвёртый квартал.",
  "topics": ["бюджет", "Q4"],
  "confidence": 0.92
}
```

- **Эндпоинты:**
  - WebSocket: `/ws/transcribe/live?protocol_id=<id>` — двунаправленный поток аудио и транскрипции
  - `POST /api/v1/transcribe/live/start` — старт сессии
  - `POST /api/v1/transcribe/live/stop` — стоп сессии
  - `POST /api/v1/screenshots/capture` — привязка скриншота к моменту

## 8. Нефункциональные требования

- **Производительность:** KPI latency живой транскрипции ≤3 сек (от реплики до появления в UI); FPS видеоплеера Телемоста ≥24; RSS backend ≤4 ГБ.
- **Защита:** все данные локально; iframe Телемоста в sandbox; никакой передачи аудио в чужие облака.
- **Горячие клавиши:** Space — play/pause iframe; Ctrl+M — mute/unmute микрофон; Ctrl+E — завершить встречу; Ctrl+S — сохранить промежуточно.
- **Кроссбраузерность:** Chromium 100+ (для `getUserMedia` без флагов), Firefox 100+, Safari 14+; Edge рекомендован.
- **Масштабируемость:** поддержка встреч до 5 часов без OOM (chunk 30 сек аудио, мониторинг RSS, автопауза).
- **Доступность:** все три панели доступны с клавиатуры; индикатор записи виден и озвучен; субтитры для видео (если поддерживается Телемост).

## 9. Технические требования

- **Frontend:** нативный JS с Web Audio API, MediaStream API, WebSocket.
- **Backend:** FastAPI с WebSocket-эндпоинтом; asyncio для параллельной обработки аудио; Whisper streaming.
- **Модели:** Whisper Large-v3 (транскрипция), pyannote (диаризация в реальном времени).
- **Особые требования:** захват системного звука через `getDisplayMedia({audio: true})` (вместо микрофона — чтобы не захватывать шум комнаты); fallback на микрофон, если системный звук недоступен.

## 10. Примечания

- **Важно:** для захвата системного звука (а не микрофона) требуется Electron-обёртка или десктопное приложение (т.к. браузеры не дают доступ к системному звуку без разрешения пользователя на запись экрана).
- Iframe Телемоста может блокировать CORS — потребуется прокси через локальный backend.
- NFR (см. Vision §9): chunk 30 сек аудио для Whisper, мониторинг RSS, лимит 1 воркер.
- Бэкап: если WebSocket обрывается, последние N минут аудио сохраняются в локальный буфер для последующей обработки.
- В Astra Linux Live Mode недоступен (нет микрофона + iframe ограничения).
