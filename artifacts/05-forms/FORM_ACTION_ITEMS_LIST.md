# FORM_ACTION_ITEMS_LIST: Список action items протокола

## 1. Общие сведения

| Поле | Значение |
|---|---|
| **Идентификатор формы** | F-HMP-10 |
| **Название формы** | Список задач (action items) протокола |
| **Путь доступа** | ProtocolView → вкладка «Задачи» / `dist/index.html` → Протокол → Задачи |
| **Цель и назначение** | Просмотр и управление задачами (action items), извлечёнными из протокола через LLM или добавленными вручную |
| **Этап бизнес-процесса** | P-01 «Подготовка протокола» — шаг 5 (задачи) |
| **Входные данные** | `action_item.*`, протокол, ораторы |
| **Выходные данные** | Обновлённые/созданные `action_item` |

## 2. Структура и навигация

- **Шапка:** заголовок «Задачи протокола», кнопки «Извлечь через AI», «Добавить вручную», фильтры.
- **Тело:** список карточек задач с полями (кто, что, когда, статус, источник).
- **Подвал:** кнопки массовых действий («Экспорт в JSON», «Отметить все как done»).
- **Адаптивность:** на узких экранах карточки перестраиваются в плотный список.
- **Табы:** 4 таба по статусу — «Открытые» (default), «В работе», «Выполненные», «Отменённые».

## 4. Поведение и события

| Событие | Реакция |
|---|---|
| Открытие формы | Загрузка action_items с фильтром по умолчанию (open), сортировка по дедлайну |
| Клик таба «Открытые» / «В работе» и т.д. | Фильтрация списка по статусу |
| Поиск (3.1.1) | Фильтрация по подстроке в `task`, debounce 300 мс |
| Изменение фильтра «Исполнитель» | Фильтрация списка |
| Изменение статуса (3.2.4) | Автосохранение через 1 сек, обновление счётчика в табах |
| Клик «Отметить done» | Моментальное обновление, completed_at = now() |
| Клик «Добавить вручную» | Модалка 3.3.1-3.3.4 |
| Клик «Извлечь через AI» | Модалка 3.4.1-3.4.3, при подтверждении POST /api/v1/ai/extract-actions |
| AI-извлечение завершено | Новые задачи появляются в списке, toast «Извлечено N задач (средняя confidence: 0.XX)» |
| Клик на реплику (3.2.7) | Переход к реплике в ProtocolView → TranscriptView с подсветкой |
| Дедлайн просрочен | Красная рамка карточки, иконка «⚠️» |
| Дедлайн сегодня | Жёлтая рамка, иконка «📅» |

## 5. Ошибки и информационные сообщения

| Тип | Условие | Вид | Текст |
|---|---|---|---|
| Ошибка | Пустая задача | Под полем | «Опишите задачу» |
| Ошибка | Дедлайн в прошлом | Под полем | «Дедлайн не может быть в прошлом» |

| Предупреждение | Удаление задачи | Модалка | «Удалить задачу "<X>"?» |
| Предупреждение | Низкая confidence (<0.5) | Иконка | «⚠️ Низкая уверенность (<0.5), проверьте задачу» |
| Информация | Извлечено | Тост | «Извлечено N задач (средняя confidence: 0.XX)» |
| Информация | Сохранение | Тост | «Изменено» |
| Информация | Все задачи done | Баннер | «Все задачи выполнены! 🎉» |

## 6. Сценарии по умолчанию (Состояния)

- **Список пуст:** «Нет задач. Извлеките через AI или добавьте вручную».
- **Только просмотр (P-02 офлайн):** карточки видны, кнопки редактирования скрыты.
- **AI-извлечение:** спиннер, остальные элементы неактивны.
- **Просроченные:** красная рамка, отдельная группа сверху.
- **Массовые действия:** мульти-чекбокс на карточках для bulk-операций.
- **Drag-and-drop сортировка:** вручную менять порядок задач (опционально).

## 7. Требования к данным (Маппинг)

### Источник данных

| Поле формы | Источник | Описание |
|---|---|---|
| Список задач | `GET /api/v1/protocols/{id}/action-items` | Все задачи протокола |
| Связанная реплика | `GET /api/v1/utterances/{id}` | Реплика-источник |
| Исполнители | `GET /api/v1/protocols/{id}/speakers` | Список ораторов (для автокомплита) |

### Пример JSON

```json
GET /api/v1/protocols/{id}/action-items → 200 OK
[
  {
    "id": "uuid",
    "owner": "Петров П.П.",
    "task": "Отправить отчёт",
    "deadline": "2026-09-15",
    "status": "open",
    "source": "llm_extracted",
    "source_utterance_id": "uuid_utt",
    "confidence": 0.87,
    "completed_at": null,
    "created_at": "2026-09-14T20:00:00Z"
  }
]

POST /api/v1/action-items
{
  "protocol_id": "uuid",
  "owner": "Сидоров",
  "task": "Связаться с подрядчиком",
  "deadline": "2026-09-18"
}

POST /api/v1/ai/extract-actions
{
  "protocol_id": "uuid",
  "provider": "hermes",
  "min_confidence": 0.6,
  "add_to_existing": true
}
```

### Эндпоинты

- `GET /api/v1/protocols/{id}/action-items` — список
- `POST /api/v1/action-items` — создать вручную
- `PATCH /api/v1/action-items/{id}` — обновить
- `DELETE /api/v1/action-items/{id}` — удалить
- `POST /api/v1/ai/extract-actions` — извлечь через AI

### Связанные таблицы БД

- `action_item` (id, protocol_id, owner, task, deadline, status, source_utterance_id, source, confidence, completed_at)
- `utterance` (action_item_id) — связь с репликой-источником

## 8. Нефункциональные требования

| Метрика | Требование |
|---|---|
| Время загрузки списка (100 задач) | p95 < 200 мс |
| Время AI-извлечения (1 час протокола) | p95 < 30 сек |
| Размер компонента | < 60 КБ |
| Toast duration | 3 сек |
| Accessibility | WCAG 2.1 AA, ARIA-live для динамических обновлений |
| Горячие клавиши | Ctrl+N (добавить), Ctrl+I (извлечь AI), Esc (закрыть модалку) |
| Локализация | ru-RU, формат дат dd.MM.yyyy |

## 9. Технические требования

- Frontend: Vanilla JS, компонент `<ActionItemsList>`.
- Backend: FastAPI с поддержкой batch operations.
- AI: интеграция с Hermes API (приоритет), GigaChat (fallback), локальная Ollama.
- Хранение: PostgreSQL, синхронизация в IndexedDB.
- Кэш: action_items в IndexedDB для офлайна.

## 10. Примечания

- Связь с US-023 (action items), US-024 (AI-извлечение), US-038 (Telegram-бот `/actions`).
- При AI-извлечении используется тот же провайдер, что выбран в user_setting.
- Confidence < 0.5 — задача помечается как «требует проверки».
- В будущем: интеграция с Яндекс.Трекером / Jira для создания задач во внешних системах.
